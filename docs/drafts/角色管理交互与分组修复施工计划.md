# 角色管理交互、分组生命周期与 Provider 代理修复施工计划

> 状态：待施工
> 计划日期：2026-08-15
> 性质：独立修复计划，不扩写 Task 142 总计划
> 范围：角色管理按钮交互、分组显示/创建/加入/删除、LLM 模型发现与 Provider Fake-IP/代理兼容

## 1. 目标

本轮解决以下用户可见问题：

1. “生成首份设计草稿”等按钮点击后没有请求、加载状态或错误反馈；
2. 新建分组不显示在左侧，选择目标分组后“加入分组”没有反应；
3. 新建分组只要求输入分组名称，由后端生成稳定且不冲突的 `groupId`；
4. 增加分组删除功能：只删除分组，不删除该组角色视觉资料；删除后全部视觉资料自动移动到 `default`；
5. 修复本机代理 Fake-IP 环境中获取 LLM 模型时报“Provider URL 不能指向私有网络”；
6. 补齐能实际发现按钮无调用、迁移丢数据和 Provider 安全回归的自动化门禁。

本轮不处理开发服务器偶发的 `worker entry not found`，不重构正文生图、角色预设解析或 NovelAI 画风串。施工时不得顺手改变这些范围外功能。

## 2. 已确认问题与根因

### 2.1 多个按钮的事件表达式没有调用函数

`TextToImageCharacterSection.vue` 中存在以下写法：

```vue
@click="void generateVisual"
@click="void copyVisualToGroup"
@click="void deleteVisual"
@click="void generatePhotoPrompt"
@click="void generateAvatar"
```

`TextToImageLlmSettingsSection.vue` 中还存在：

```vue
@click="void buildTestPreview"
```

这些表达式只读取并丢弃函数引用，不会执行函数。因此不会发送请求，也不可能进入函数内部已有的 `saving`、`activeAction`、通知或错误处理。

对照项：`@click="generateVisual"` 可以作为 Vue 方法处理器调用；`@click="void generateVisual()"` 也会显式调用并丢弃 Promise。修复必须采用其中一种真实调用形式。

相关文件：

- `app/components/novel-ide/text-to-image/TextToImageCharacterSection.vue`
- `app/components/novel-ide/text-to-image/TextToImageLlmSettingsSection.vue`

### 2.2 空分组被侧栏过滤

当前侧栏数据使用：

```ts
const visualGroups = computed(() => groups.value.filter((group) => group.characters.length > 0));
```

模板只遍历 `visualGroups`，所以刚创建且还没有角色视觉资料的分组必然不可见。目标分组下拉框遍历的是完整 `groups`，因此会出现“下拉框里有分组，左侧树里没有”的矛盾状态。

目标规则应是：

- 分组层显示全部分组，包括空分组；
- 角色层只显示至少有一份视觉 JSON 的角色；
- 尚未录入视觉资料的 Lorebook 角色不进入视觉资料树。

### 2.3 “加入分组”服务链路已存在，前端入口断开

`copyVisualToGroup()` 已经具备：

- 校验来源视觉 ref 和目标分组；
- 调用 `character-library/visual.copy`；
- 消费后端返回的目标 `groupId + characterId + visualId`；
- 展开目标节点、通知成功并重新加载树。

当前主要断点是按钮没有调用该函数。修复事件后仍需验证双击锁、失败恢复、目标已存在同角色时的版本创建行为。

### 2.4 分组创建合同仍要求浏览器提供技术 ID

当前前端要求填写“分组 ID”和“显示名称”，POST API 的 Zod schema 也强制要求 `groupId`，服务层再把它作为目录名。

这与“作者只输入分组名”的要求不符，也把路径安全和冲突处理错误地下放到了浏览器。

相关文件：

- `app/components/novel-ide/text-to-image/TextToImageCharacterSection.vue`
- `server/api/text-to-image/character-library/groups.post.ts`
- `server/text-to-image/character-visual-library.service.ts`

### 2.5 当前删除分组只能删除空组

现有 `deleteGroup()` 在分组存在角色时直接报错，空组则递归删除目录。目标合同改为：非 `default` 分组无论是否为空都可以删除；非空组先把全部视觉资料无损迁移到 `default`，确认迁移成功后才删除来源分组。

### 2.6 Provider 私网报错来自 Fake-IP 与直连安全策略冲突

当前环境：

```text
opencode.ai -> 198.18.0.23
opencode.ai -> fdfe:dcba:9876::1a
HTTPS_PROXY=http://127.0.0.1:7897
HTTP_PROXY=http://127.0.0.1:7897
```

通用 Provider 请求使用安全 dispatcher 直连，并校验 DNS 返回的每一个地址；IPv6 ULA 被正确判定为私网，所以请求在建立 HTTP 连接前失败。代码虽然能读取代理环境变量，但当前测试明确要求通用 Provider 请求不应用环境代理。

`https://opencode.ai/zen/go/v1/models` 本身可以返回模型列表，因此不是 Base URL 格式错误或供应商接口不可用。

相关文件：

- `server/text-to-image/llm-models.ts`
- `server/text-to-image/provider-fetch.ts`
- `server/text-to-image/provider-url-policy.ts`
- `server/text-to-image/provider-fetch.test.ts`
- `server/api/text-to-image/llm/models.post.ts`
- `app/components/novel-ide/text-to-image/TextToImageLlmSettingsSection.vue`

### 2.7 现有测试无法发现按钮无调用

当前 `workbench-entry.contract.test.ts` 主要检查源码中是否包含 API 路径，没有挂载组件并点击按钮。`@click="void generateVisual"` 是语法合法的表达式，typecheck 也不会报错。

因此本轮不能只修改模板，必须补“事件真实调用”的静态门禁和 DOM 交互测试。

## 3. 产品合同

### 3.1 按钮与请求反馈

- 所有异步按钮必须真实调用对应函数。
- 点击后立即显示该动作专属 spinner 和阶段文案，并禁用会冲突的操作。
- 双击或连续点击只允许产生一个写请求。
- 成功、失败和取消都必须在 `finally` 中结束 pending。
- 当前面板可恢复错误使用局部错误；跨入口或 Dialog 已关闭后的结果使用 `useNotification()`。
- 首份草稿、加入分组、删除 JSON、生成照片 Prompt、生成照片、组合提示词预览必须逐一验收，不能只验收截图中的两个按钮。

### 3.2 左侧视觉资料树

- 展示全部分组，包括空分组。
- 空分组显示数量 `0` 和“暂无视觉资料”，仍可折叠、重命名、排序、启用和删除。
- 分组内部只显示已经存在视觉 JSON 的角色。
- 创建分组成功后无需刷新即可显示，并自动展开或选中新分组。
- “加入分组”成功后展开目标分组和角色，选中新生成的视觉 JSON；来源资料继续保留。

### 3.3 创建分组

前端：

- 只保留一个必填输入框“分组名称”；
- 不展示或要求作者理解 `groupId`；
- 同名冲突时保留输入内容并就地显示错误。

API：

```ts
type CreateCharacterGroupRequest = {
    projectRoot: string;
    name: string;
};
```

- 请求体继续使用 Zod `.strict()`；浏览器提交 `groupId` 必须被拒绝；
- 服务端规范化名称，拒绝空名称；
- 同一 Project 内规范化后的显示名称必须唯一，创建或重命名同名返回 `409`；
- 服务端使用 `group-${crypto.randomUUID()}` 生成内部 ID；碰撞时重新生成；
- `groupId` 创建后永久稳定，重命名不改目录和引用；
- API 返回完整 group，前端只能消费返回 ID，不能本地推导。

### 3.4 删除分组

核心语义：

- `default` 永远不能删除；
- 删除其它分组只删除分组本身；
- 分组内全部角色视觉资料自动移动到 `default`；
- 角色原始 Markdown、视觉 JSON 内容、照片资产和历史 Job 快照不得删除或改写；
- 任一步失败都必须保留来源分组完整可用，不允许半迁移。

#### 3.4.1 删除前预检

删除采用两步 API：

1. 只读预检，返回影响摘要和 revision；
2. 用户确认后携带 `expectedRevision` 提交迁移删除。

预检至少返回：

```ts
type DeleteGroupPreview = {
    groupId: string;
    revision: string;
    characterCount: number;
    visualCount: number;
    invalidFileCount: number;
    fileNameConflictCount: number;
    visualIdConflictCount: number;
    managedReferenceCount: number;
    defaultEnabled: boolean;
};
```

确认 Dialog 必须明确写出“视觉资料将移动到默认分组”，不能使用让用户误以为视觉资料也会删除的普通删除文案。预检后数据变化时提交返回 `409`，要求重新确认。

#### 3.4.2 合并与冲突规则

- 目标 `default` 没有同角色时，迁移整个角色目录；
- `default` 已有同 `characterId` 时合并两个 manifest，不覆盖已有视觉版本；
- 目标文件名按 Windows 大小写不敏感规则检查冲突；冲突时使用 `<原文件名主体>-moved-<8位随机标识>.json`，并更新 manifest；
- `visualId` 在目标中未占用时保持不变；极端冲突时生成新 UUID，并返回旧 ref → 新 ref 映射；
- `default` 已有合法 `activeVisualId` 时保持不变；目标角色原先不存在或没有合法生效项时，使用来源角色的生效视觉；
- 损坏 JSON 按原始字节迁移，继续作为错误节点可见，不得因为解析失败丢弃；
- 照片位于受控资产目录时只保留引用，不删除、不重复复制；
- 当前 Project 配置内受管的固定 `groupId/visualId` 引用按 ref 映射更新；历史 Job 和历史资产快照保持不可变；
- 删除已启用分组时只从启用集合移除来源 ID，不隐式启用 `default`。如果 `default` 未启用，完成通知明确提醒迁移资料当前不会参与正文自动扫描。

#### 3.4.3 事务和恢复

跨多个文件和目录不能只靠一次 `try/catch` 宣称原子。服务层必须：

1. 获取 Project 级视觉库写锁；
2. 预检来源、目标、manifest、受管引用和磁盘文件，生成确定性迁移计划；
3. 在同一卷的 `.agent/tmp` 或视觉库受控事务目录中准备目标文件、合并 manifest、新分组清单和引用更新；不得把业务临时数据散落到 Project 根；
4. 校验迁移前后角色数、视觉文件数、字节数/内容哈希和 ref 映射；
5. 使用事务日志、备份和可恢复 rename 提交；
6. 只有目标和元数据全部生效后才移除来源目录；
7. 任一步失败按日志恢复旧 `default`、旧分组清单、旧引用和来源目录；
8. 服务启动或下一次库操作时识别未完成事务，执行恢复或安全续作；
9. 成功后清理事务目录并返回迁移摘要及 ref 映射。

前端不得先乐观隐藏分组。只有服务端提交成功后才能刷新树并切换到 `default`。

### 3.5 Provider Fake-IP 与受控代理

模型发现和正式 LLM 请求必须共用同一出站策略，不能只修“获取模型”。

直接模式：

- 保留 HTTP/HTTPS、凭据、片段、localhost、IP 和 DNS 地址校验；
- 补齐 `198.18.0.0/15` 等非公网保留地址，不能把 Fake-IP 当成公网目标；
- 继续校验 socket 实际连接地址和每次重定向。

受控代理模式：

- 只自动信任明确配置且可达的 loopback HTTP/HTTPS 代理：`127.0.0.1`、`[::1]` 或 `localhost`；
- 使用 `ProxyAgent` 让受信任本机代理解析公网域名；
- 非 loopback 环境代理不得自动接收 Provider API Key；
- 代理模式仍拒绝 URL 中的私网字面量、localhost、`.local`/`.localhost`；
- 代码注释和测试必须明确：代理模式把目标域名解析信任交给用户配置的本机代理；
- HTTPS 不得降级到 HTTP；跨源重定向不得携带 Authorization、Cookie 或代理凭据；重定向到显式私网地址继续拒绝；
- 代理不可用时不得改成允许私网直连。

错误反馈至少区分：URL 策略拒绝、DNS/Fake-IP、代理不可用、Provider 连接失败、鉴权失败和 HTTP 错误。任何错误不得暴露 API Key、完整响应头或代理凭据。

## 4. API 调整

| API | 调整 |
| --- | --- |
| `POST character-library/groups` | 只接收 `projectRoot + name`；服务端生成 ID；同名返回 `409` |
| `GET character-library/groups.delete-preview` | 新增只读预检；返回影响摘要和 revision，不修改文件 |
| `DELETE character-library/groups` | 接收 `projectRoot + groupId + expectedRevision`；迁移到 `default` 后删除来源，返回统计和 ref 映射 |
| `POST character-library/visual.copy` | 保持现有返回目标 ref；前端真实调用并消费结果 |
| `POST llm/models` | 使用与正式 LLM 请求相同的直连/受控代理策略和错误投影 |

所有 API 继续使用认证、Project Root 解析、路径 containment、Zod `.strict()` 和 `resolveApiErrorMessage()`。

## 5. 前端动作状态

建议在现有动作联合类型中至少覆盖：

```ts
type CharacterWorkbenchAction =
    | "create_group"
    | "delete_group"
    | "copy_to_group"
    | "delete_visual"
    | "generate_design"
    | "generate_photo_prompt"
    | "generate_photo"
    | null;
```

每个动作包含 `kind`、`phase` 和 `startedAt`。同一面板同一时间只允许一个冲突写操作；按钮是否转圈只看自己的动作类型。异步函数必须在 `finally` 清理状态。

删除分组流程：

1. 点击删除后加载影响摘要；
2. Dialog 显示迁移数量、冲突、引用更新和 `default` 启用提醒；
3. 用户确认后进入 `delete_group`，锁定来源 `groupId`；
4. 成功后消费 ref 映射、刷新树、展开 `default` 并恢复当前视觉选择；
5. 失败后来源分组和当前选择保持不变；
6. `409` 时刷新摘要，不能使用旧确认继续提交；
7. 双击只发送一个删除提交，删除请求不自动重试。

退出条件：Fake-IP 环境请求成功，私网和凭据安全测试继续通过；没有使用 `allowPrivateNetwork: true` 绕过。

## 7. 测试矩阵

### 7.1 事件和 UI

- 模板中不存在 `@click="void functionName"` 等只取引用表达式；
- 点击首份草稿、加入分组、删除 JSON、照片 Prompt、照片生成、组合提示词预览均发送一次请求；
- 请求期间按钮转圈并禁止重复提交；
- 失败显示错误并恢复按钮；
- 空分组可见、可折叠、有空状态；

### 7.2 分组服务与文件

- `default` 自动存在且不能删除；
- 服务端生成 ID、碰撞重试、同名创建/重命名拒绝；
- 空组删除；单角色和多角色非空组删除；
- `default` 中无同角色和已有同角色两种迁移；
- 单份和多份视觉 JSON；有效与损坏 JSON；Unicode `characterId`；
- Windows 大小写文件名冲突和 `visualId` 冲突；

- 重启后可恢复未完成事务；
- 迁移前后角色数、视觉文件数、字节数/哈希一致。

### 7.3 Provider 安全与连接

- 正常公网 DNS 无代理时继续直连；
- Fake-IP + `127.0.0.1:7897` 时模型发现和正式 LLM 请求通过代理；
- 非 loopback 环境代理不被自动信任；
- `127.0.0.1`、RFC1918、`198.18.0.0/15`、IPv6 ULA、链路本地和组播/保留地址继续拒绝；
- 代理模式拒绝显式私网 URL、localhost、`.local`/`.localhost`；
- HTTPS 降级、跨源携带 Authorization 和重定向到私网均拒绝；
- 代理不可用、DNS 失败、鉴权和 HTTP 错误反馈可区分且不泄漏凭据；
- `https://opencode.ai/zen/go/v1/models` 返回非空模型列表。

## 8. 验收标准

全部满足才能报告完成：

1. “生成首份设计草稿”点击后立即出现等待状态并真实进入 LLM 请求，成功显示草稿，失败显示错误。
2. 六个已确认的无效按钮均由真实点击触发，模板门禁能阻止同类回归。
3. 左侧显示所有分组，包括空分组；分组内部仍只显示已录入视觉资料的角色。
4. 新建分组只输入名称，服务端生成不可冲突的稳定 ID；同名分组不会产生。
5. “加入分组”成功复制资料、保留来源、展开目标并选中新 JSON；失败可重试且不会重复提交。
6. 删除非 `default` 分组后，该组全部角色视觉资料无损进入 `default`，角色 Markdown、照片和历史 Job 不变。
7. 删除迁移遇到文件名、`visualId`、同角色合并或中途写入故障时不覆盖、不丢失，并能恢复原分组。
8. 删除分组前显示准确影响摘要；成功和失败都有明确反馈，`default` 未启用时有提醒。
9. 当前 Fake-IP + loopback 代理环境可获取 `opencode.ai` 模型并执行同策略的正式 LLM 请求。
10. 私网 URL、危险重定向和跨源凭据泄漏仍被拒绝，没有通过关闭安全策略换取可用性。
11. 聚焦测试和 typecheck 有真实命令与结果；浏览器或真实 Provider 验收未执行时明确写“未执行”。

## 10. 禁止的实现方式

- 不允许只修截图中的两个按钮而遗漏同类事件表达式；
- 不允许用源码包含函数名或 API 字符串代替真实交互测试；
- 不允许继续过滤整个空分组节点；
- 不允许让浏览器生成或提交 `groupId`，也不允许把中文显示名直接作为目录名；
- 不允许删除非空分组时直接 `fs.rm`、先删来源再复制、忽略损坏 JSON、覆盖 `default` 同名文件或只改分组清单留下孤儿目录；
- 不允许在迁移失败时用“重复一份但没有丢失”作为成功结果；成功状态必须只有一个确定真相源；
- 不允许为了 Fake-IP 设置 `allowPrivateNetwork: true`、把 `198.18.0.0/15` 当公网，或把 API Key 交给任意远程环境代理；
- 不允许修改范围外的角色提示词、正文生图、NovelAI 参数或 `worker entry not found` 处理。
