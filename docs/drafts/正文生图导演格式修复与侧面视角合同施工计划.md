# 正文生图导演格式修复与侧面视角合同施工计划

> 状态：实现已落地，待真实验收与当前章节恢复
> 计划日期：2026-08-17
> 性质：Task 142 的独立修复计划，不扩写历史总计划
> 范围：`illustration.director` LLM 回复格式修复、角色调用稳定合同、`from side` 视觉资料选择、写入前门禁与当前失败章节恢复

## 1. 目标

本轮解决点击正文“生成图片”后才暴露角色调用格式错误的问题，并补齐 `from side` 合同：

1. `illustration.director` 在 LLM 回复进入正文占位符之前，把可确定修复的角色调用规范化为标准 `${...}$`；
2. `from side`、`side view`、`three-quarter view` 等非背面角度合法，使用正面角色视觉资料，同时保留原始角度 Tag；
3. `from behind`、`from back`、`back`、`behind` 使用背面角色视觉资料；
4. 不可安全修复的截断 JSON、非法字段和非法身体状态在 LLM 阶段失败并参与现有重试，不写入章节；
5. L2 正文占位符只持久化经过规范化和校验的调用，点击“生成图片”不再承担首次发现 LLM 格式错误的职责；
6. 当前已经写入章节的失败占位符通过整体 reroll 重建，不在运行时永久保留一条旧数据兼容分支。

本轮不改变角色视觉 JSON 字段、角色匹配优先级、NovelAI 参数、最终 Prompt Bundle、队列间隔或图片资产格式。

## 2. 已确认事实与根因

### 2.1 当前失败样本

本次 `deepseek-v4-flash` 原始回复包含 `13` 个角色调用：

- `13/13` 写成 `${...}`，缺少结尾 `$`；
- `6/13` 使用 `angle: "from side"`；
- 这些调用分布在当前章节的 `8` 个正文生图占位符中，因此 `8` 个占位符都会先因未闭合调用失败；
- 只补结尾 `$` 后，含 `from side` 的调用还会被当前编译器以“angle 无效”拒绝。

生成接口在 `queue.enqueue()` 之前调用 `compileBodyPrompt()`，所以失败发生在 NovelAI 队列之前，不是 NovelAI 凭据、网络或采样参数问题。

### 2.2 st-chatu8 的实际行为

参考实现：<https://github.com/damoshen123/st-chatu8/blob/main/index.js#L27026-L27095>

`st-chatu8` 的 JSON 调用合同是：

- JSON 对象中存在 `angle` 就按角色调用处理；没有 `angle` 则按独立服装处理；
- `angle` 不使用 front/back 枚举白名单；
- 只有角度文本包含 `from behind` 时才选择背面五官和背面身体/服装字段；
- 其他角度，包括 `from side`，全部选择正面字段；
- 调用扫描使用成对的 `$...$`，不会修复缺少结尾 `$` 的回复。

NeuroBook 不原样复制上游的宽松输入：`angle` 仍要求为非空字符串，身体状态仍严格校验；但采用其“背面关键词决定 DNA，其余角度使用正面 DNA”的核心语义，并保留本仓库已经支持的背面同义词。

### 2.3 本仓库合同与实现发生漂移

`docs/superpowers/specs/2026-08-10-chatu8-preset-compatibility-design.md` 已规定：

- `angle` 原文保留给构图 Prompt；
- `from behind`、`from back` 或 `back` 选择背面 DNA；
- 其他角度选择正面 DNA。

当前 `body-prompt-compiler.ts` 却只接受 `front` / `from front` / `back` / `from back` / `from behind` / `behind`，把 `from side` 当成非法值。问题不是需要发明新语义，而是稳定 Reference、实现和测试没有落实既定设计。

### 2.4 校验发生得太晚

当前链路是：

```text
LLM 回复
  → 只解析 <image>/<regex>/<prompts>
  → 写入 L2 正文占位符
  → 用户点击“生成图片”
  → compileBodyPrompt 首次解析角色调用
  → 失败
```

`body-image-llm.ts` 能因 XML 结构错误重试，但不会检查 `<prompts>` 内的角色调用；`body-image-insert.service.ts` 也不验证调用便直接写入章节。因此，格式错误跨过了 LLM 交互边界，变成用户在最后一步才看到的错误。

## 3. 责任边界

### 3.1 illustration.director

`illustration.director` 是正文生图的服务端 LLM 回复格式领域层，不重新引入旧版 Agent Profile、九工具规划链路或多轮 ShotIntent 工作流。现有 `body-image-llm.ts` 保留请求发送和最多 2 次重试；director 作为其中唯一的 L1 调用规范化与校验入口。

它负责：

- 对应用 AI 替换规则后的 LLM 回复执行确定性格式规范化；
- 解析 L1 `<image>` 块；
- 校验每个基础 Prompt、分角色 Prompt 和分角色负面 Prompt 中的角色调用；
- 将不可修复结果抛回现有“最多重试 2 次”机制；
- 只向下游返回已经规范化、可以安全写入 L2 的结构化块；
- 记录修复种类和数量，不记录完整正文、完整 Prompt 或凭据。

它不负责：

- 猜测缺失的角色名、字段值或 JSON 内容；
- 把非法语义改成“看起来能跑”的值；
- 解析 Project 角色身份或选择具体视觉版本；
- 组装最终 NovelAI Prompt、创建队列任务或保存资产；
- 为修复格式额外调用另一个 LLM；
- 直接管理 HTTP 请求、Provider 凭据或重试计数。

### 3.2 共享角色调用 codec

新增单一共享领域模块，供 director 的写入前校验和生成按钮后的编译器共同消费。它负责：

- 平衡扫描 `${...}$`，正确处理嵌套对象、字符串内花括号和转义引号；
- 解析角色/独立服装调用对象；
- 严格校验 `name`、`angle`、`upperBody`、`lowerBody`；
- 推导 `front` / `back` 视觉方向；
- 输出规范化调用文本及安全诊断位置。

禁止 director 与 `body-prompt-compiler.ts` 各自维护一套正则、字段默认值或角度列表。

### 3.3 正文 Prompt 编译器

编译器只消费已经符合调用合同的 Prompt，并负责：

- 按角色 ID、分组、视觉版本和别名解析 Project 视觉资料；
- 按 codec 推导出的 `front` / `back` 选择正背面五官、身体和服装字段；
- 把原始 `angle` 文本作为构图 Tag 保留在展开结果中；
- 收集角色负面 Prompt；
- 阻止任何未展开的调用进入 NovelAI 队列。

编译器不再负责修复 LLM 遗漏的结尾 `$`。这样 L2 是规范化数据，而不是等待生成按钮继续修补的半成品。

## 4. 产品与数据合同

### 4.1 标准角色调用

标准格式：

```text
${"name":"Saki Terashima","angle":"from side","upperBody":"sfw","lowerBody":"sfw"}$
```

字段合同：

- `name`：必填非空字符串；后续由 Project 身份解析器按稳定 ID、精确别名和唯一候选解析；
- `angle`：角色调用必填非空字符串；原文保留为 NovelAI 构图 Tag；
- `upperBody` / `lowerBody`：只允许 `sfw`、`nsfw`、`hidden`；
- 没有 `angle` 的对象是独立服装调用，身体字段只允许 `visible`、`hidden`；
- 未知字段沿用当前调用解析合同；本轮不新增 strict unknown-field 行为，已登记的 inline character/outfit 扩展字段继续可用。

### 4.2 角度到视觉资料的映射

先对 `angle` 做 trim、Unicode NFKC 和不区分大小写比较，但最终输出保留 trim 后的原文。

```text
from behind / from back / back / behind → back DNA
其他非空角度                              → front DNA
```

因此：

- `from side`、`side view`、`three-quarter view`、`from above`、`from below` 使用正面视觉资料；
- 原始角度仍加入最终角色 Tag；
- 若基础 Prompt 已经包含相同角度，最终 Prompt Bundle 的既有去重规则负责去重；
- 不创建第三套“侧面 DNA”字段，也不拿背面字段拼接侧面外观。

### 4.3 director 允许的确定性修复

允许修复的唯一新增情况：

```text
输入：${"name":"Saki Terashima",...}
输出：${"name":"Saki Terashima",...}$
```

只有同时满足以下条件才补结尾 `$`：

1. 从 `${` 开始可以平衡扫描到完整最外层 `}`；
2. 对象可以被 JSON.parse；
3. 对象满足角色调用或独立服装调用 schema；
4. `}` 后是安全边界：字符串结尾、空白、逗号或 XML 标签边界，而不是另一个标识符；
5. 补全后再次解析得到与原对象相同的字段和值。

修复必须幂等：规范输入再次处理不得变化。

以下情况不得猜测修复：

- JSON 在字符串、数组或嵌套对象中途截断；
- 缺少引号、冒号、字段值或角色名；
- `upperBody` / `lowerBody` 存在但值非法；
- `angle` 不是字符串或是空字符串；
- 一段残缺调用与后续普通 Tag 无法确定边界。

不可修复时 director 抛出带 image 序号、Prompt 槽位和字段原因的错误，并触发下一次 LLM 尝试。错误信息不得回显整章正文或完整私人 Prompt。

### 4.4 L1、L2 与队列边界

```text
LLM 原始回复
  → AI 替换规则
  → illustration.director 确定性修复
  → L1 XML + 调用 schema 校验
  → L2 规范占位符
  → 用户点击生成
  → 严格编译角色视觉资料
  → 最终 Prompt Bundle
  → NovelAI 队列
```

- L1 原始回复和修复前内容不写 Project；
- L2 只保存规范 `${...}$`；
- L2 写入函数自身再执行一次只读断言，防止未来新增调用方绕过 director；
- 队列请求和资产快照中不得残留 `${`、`}$` 或未解析调用对象。

## 7. 当前数据恢复

新实现只保证新 LLM 回复在写入前被修复。当前章节已经落盘的 `8` 个坏占位符不自动迁移，原因是：

- L2 按合同应当是规范数据；
- 为单次开发期坏数据保留长期编译器兼容会模糊 director 与编译器责任；
- 当前章节可以通过现有整体 reroll 重新生成，历史图片和资产不会被删除。

推荐恢复步骤：

1. 部署本修复；
2. 在当前章节重新执行正文生图并确认整体 reroll；
3. director 修复新回复中的缺失 `$`，保留 `from side`；
4. 写入新的规范占位符；
5. 先生成第一张侧面图，再抽查一张背面图；
6. 旧失败占位符随整体 reroll 清理，历史资产保持不变。

若 LLM 回复无法重现原来的图片规划，才单独提出“对当前章节做一次性受控修复”的数据操作；该操作必须先备份并逐个解析验证，不纳入通用运行时代码。

## 8. 非目标与风险

### 非目标

- 不恢复旧 `illustration.director` Agent Profile；
- 不新增第二次 LLM 格式修复请求；
- 不自动补写缺失的业务字段；
- 不新增侧面角色视觉字段；
- 不修改已生成资产、历史 Job 或冻结的 Prompt Bundle；
- 不顺手调整角色分组、触发词、画风串、NovelAI 调度或后处理链路。

### 风险与控制

- **误把普通 `${...}` 文本当调用：** 修复器只运行在 L1 Prompt 槽，并要求完整 JSON 对象和调用 schema。
- **嵌套对象被正则截断：** 使用平衡扫描并覆盖字符串转义测试，不继续扩展当前单正则。
- **角度误判背面：** 背面只识别登记的短语/词，不用任意 `includes("back")` 命中 `backlighting`。
- **director 与编译器再次漂移：** 两者共同消费同一个 codec，Reference 记录唯一语义。
- **修复掩盖模型质量问题：** 只修缺失的结尾分隔符；其他错误保留失败和重试，诊断记录修复计数。
- **当前章节仍失败：** 明确需要整体 reroll；不宣称代码升级会自动改写已落盘占位符。

## 9. 完成定义

只有同时满足以下条件才能标记完成：

- `illustration.director` 成为 LLM 回复格式规范化和 L1 调用校验的唯一入口；
- `from side` 及其他非背面角度按 front DNA 成功展开并保留原始角度；
- 背面同义词稳定选择 back DNA；
- 可修复的缺结尾 `$` 不再进入 L2；不可修复输入不会写入章节；
- 生成队列中不存在未展开角色调用；
- Reference、Task 142 walkthrough 和实际实现一致；
- 聚焦回归、文生图回归、类型检查和 `git diff --check` 结果如实记录；
- 当前失败章节已按授权完成恢复验证，或明确记录为“未执行”；
- 未经用户明确许可，不合并 PR、不关闭 Issue、不部署。
