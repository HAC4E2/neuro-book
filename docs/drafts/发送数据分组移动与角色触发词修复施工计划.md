# 发送数据状态、角色分组移动与触发词严格化施工计划

> 状态：已落地（2026-08-15 施工完成；实施记录见 [Task 142 walkthrough](../tasks/142-text-to-image-chatu8-port/README.md) 的「发送数据状态、角色分组移动与触发词修复施工」小节）
> 计划日期：2026-08-15
> 性质：独立修复计划，不扩写 Task 142，也不改写上一份独立计划
> 范围：发送数据选中/保存状态、角色分组启用标识、视觉资料跨组移动、角色触发词格式与扫描、角色身份保存一致性

## 1. 目标

本轮修复以下用户可见问题：

1. “发送数据”没有足够明显的选中标识，也没有区分“页面内刚勾选”和“后端已经保存、会实际发送”两种状态；
2. “加入分组”实际复制当前视觉资料，导致来源分组和目标分组同时出现相同内容；
3. “当前启用角色分组”只有不明显的原生复选框，用户无法快速判断哪些分组参与正文自动扫描；
4. 角色触发词统一改为只使用半角竖线 `|` 分隔，不再支持英文逗号 `,` 或中文逗号 `，` 作为运行时分隔符；
5. 保存任何视觉字段时，后端会擅自把角色中文名追加到 `triggerWords`；修改中文名还会累积旧名称；
6. 补齐触发词扫描中的英文大小写、显式触发词回退、跨角色歧义和多视觉版本身份一致性；
7. 建立能阻止 UI 状态不明显、跨组复制、隐式字段改写和触发词解析分叉再次出现的自动化门禁。

本计划只定义施工合同和验证方式，不在计划编写阶段修改业务代码、Project 数据或用户视觉 JSON。

## 3. 已确认现状与根因

### 3.1 发送数据存在两层状态，但界面只显示一个弱复选框

`TextToImageSendDataSection.vue` 中 Lorebook、角色和服装都使用原生 checkbox。切换后只改变组件内的 `sendData`；只有点击“保存选择”并完成 `PUT /api/text-to-image/project-send-data` 后，选择才写入 Project。

当前没有：

- 保存前快照；
- `dirty` 计算；
- 离开页面保护；
- 行级强调色、状态徽标或选中数量；
- “固定发送”和“自动扫描”之间的用户可见解释。

后端正文请求读取磁盘保存值，再把固定角色与正文扫描角色合并。固定角色即使正文未命中触发词也会发送，并覆盖同 `characterId` 的自动扫描结果。因此 UI 必须把“已勾选但未保存”和“已保存、下一次请求会固定发送”分开表达。

### 3.2 当前“加入分组”是复制，不是移动

前端调用 `character-library/visual.copy`，后端 `createCopy()` 保留来源文件，在目标组创建新的 `visualId`，完整复制角色字段、服装和照片引用。该行为会让两个分组出现内容相同的视觉资料。

复制还有照片生命周期风险：两个 JSON 可能引用同一照片路径，而删除任一视觉资料会清理照片资产，使另一份副本留下失效引用。

### 3.3 分组启用状态已生效，但展示不足

`CharacterVisualLibraryService.setEnabledGroups()` 能正确保存启用集合，`getEffectiveVisuals()` 也只读取启用分组并按 `sortOrder` 解决同角色覆盖。问题集中在 UI：当前分组卡片不根据 `group.enabled` 改变背景、边框和文案，只有原生 checkbox；请求期间也没有显示正在更新哪个分组。

### 3.4 触发词解析和保存存在三套不一致合同

当前代码至少存在以下不一致：

1. `body-character-scanner.ts` 使用 `raw.split(",")`，只识别英文逗号；
2. 新视觉库 `normalizeVisualIdentity()` 保存时按英文逗号拆分，并无条件追加中文名；
3. 旧视觉服务 `normalizeCharacterIdentity()` 复制了同样的追加逻辑；
4. `buildCharacterTriggerWords()` 无论显式触发词是否为空，都会再加入英文名和中文名，与“为空时回退”的注释和产品预期不一致；
5. 英文匹配大小写敏感；
6. 不同 `characterId` 命中相同触发词时会同时注入，没有返回可理解的歧义错误。

所以“删除角色名后保存又出现”不是前端回显问题，而是后端真实改写了本地 JSON。任何字段保存都会经过该规范化函数，因此只修改外貌或服装也可能顺带污染触发词。

### 3.5 角色身份只保存当前 JSON，可能跨版本分叉

当前顶部“保存”只向 `visual.put` 提交当前 `groupId + characterId + visualId`。如果同一角色有多个视觉版本，编辑中文名、英文名或触发词只修改当前 JSON，其它版本继续保留旧身份。

本轮延续既定合同：

- `characterId`、中文名、英文名和 `triggerWords` 属于逻辑角色身份；
- 外貌、身体 Tag、负面 Tag、服装和照片属于视觉版本；
- 身份编辑必须同步该 `characterId` 的全部视觉 JSON；
- 普通视觉编辑只能修改当前 JSON，不得隐式改写身份字段。

## 4. 固定产品合同

### 4.1 发送数据与启用分组是两种不同功能

- “发送数据”中的 Lorebook、角色和独立服装是固定发送选择；
- 固定角色即使正文没有出现触发词也会发给 LLM；
- “当前启用角色分组”只决定正文自动角色扫描的候选范围；
- 固定选择以服务端已保存快照为准，页面未保存修改不参与下一次请求；
- UI 必须同时展示当前编辑状态和已保存状态，不能让一个复选框同时承担两种含义。

### 4.2 跨组操作改为移动当前视觉 JSON

“加入分组”改名为“移动到分组”，操作对象是当前明确选中的 `visualId`，不再调用复制接口。

规则如下：

- 来源分组删除当前视觉 JSON，目标分组接收该视觉 JSON；
- 如果它是来源 `groupId + characterId` 的最后一份视觉资料，来源角色节点和空 manifest 目录一并移除，因此旧分组不再显示该角色；
- 如果来源角色还有其它视觉 JSON，来源只保留其它设计；这用于把不同故事阶段的不同视觉版本拆分到不同分组；
- 目标组没有同角色时创建角色目录和 manifest；
- 目标组已有同角色时把移动文件合并为新的视觉版本，不覆盖现有版本；
- 显式移动成功后，移动的视觉设为目标组当前生效版本，并在侧栏选中；
- 如果移动的是来源当前生效版本且来源仍有其它版本，来源选择 `updatedAt` 最新的合法剩余版本作为新的当前生效项；时间相同时按 `visualId` 稳定排序；
- 移动不复制、不删除、不重新编码照片资产，照片路径保持原样；
- 同一次操作只能得到一个确定的目标真相源。

### 4.3 目标已存在相同内容时合并，不生成第三份

为了处理用户已经通过旧“复制”功能形成的重复资料，移动预检应计算视觉内容指纹。指纹忽略 `visualId`、文件名、manifest 时间戳和来源字段，但包含完整角色视觉字段、服装顺序/内容和照片路径。

- 目标存在内容指纹相同的视觉时，不再写入第三份文件；
- 来源 ref 映射到目标已有 ref；
- 来源视觉从来源 manifest 移除；
- 受管发送数据引用改为目标已有 `groupId + visualId`；
- 不删除共享照片资产；
- 目标相同内容有多份时返回冲突预检，不静默任选一份，要求用户先处理重复项。

内容指纹只用于本次明确移动的冲突处理，不建立后台自动去重任务。

### 4.4 触发词只允许 `|`

新合同示例：

```text
艾莉希雅 | 爱莉 | Elysia
```

硬规则：

- 运行时唯一分隔符是半角竖线 `|`；
- 保存后的规范格式为单个空格包围的 ` | `；
- 英文逗号 `,` 和中文逗号 `，` 不再具有分隔含义；
- 为避免静默误匹配，迁移完成后的新输入只要包含 `,` 或 `，` 就直接校验失败，提示“触发词只能使用 | 分隔”；
- 不允许连续空项，例如 `艾莉希雅 || 爱莉`；
- 去除每项首尾空白，按 Unicode NFKC 规范化后去重；显示保留第一次输入的文本形式；
- 英文匹配使用 Unicode 兼容规范化和不区分大小写比较；中文继续使用现有子串命中行为；
- 显式列表非空时只使用显式触发词，不再自动追加中文名或英文名；
- 显式列表为空时，扫描阶段临时回退到非空的中文名和英文名，但绝不把回退名称写回 JSON。

### 4.5 历史逗号格式只做一次性迁移

“只保留 `|`”不等于直接让现有 Project 的逗号格式全部失效。逗号只允许出现在一次性迁移器中，不能保留在正常解析、保存或扫描路径。

迁移规则：

1. Project 视觉库缺少 `triggerWordsFormat: "pipe-v1"` 标记时视为待迁移；
2. 获取 Project 级视觉库写锁并恢复未完成事务；
3. 枚举 manifest 中全部合法视觉 JSON；
4. 迁移器单独按旧合同识别 `,` 和 `，`，去空白、去空项、去重并输出 ` | `；
5. 不追加中文名或英文名；空触发词保持空；
6. 损坏 JSON 不丢弃、不隐藏，记录为迁移警告；修复后保存必须遵守 `|`；
7. 写入前备份原文件并计算哈希，全部写入和复读校验成功后才提交 `pipe-v1` 标记；
8. 任一写入失败回滚全部已改文件和格式标记；
9. 标记存在后，运行时代码不得再调用逗号拆分函数；
10. 旧 `character-visual.*` 写入口同样执行严格 `|` 校验，不能绕过新合同重新制造逗号数据。

迁移报告至少包含：扫描文件数、转换文件数、无需修改数、损坏文件数、失败文件和回滚状态。不得记录完整角色视觉内容。

## 5. 前端施工

### 5.1 发送数据选择态

在 `TextToImageSendDataSection.vue` 中保留两份状态：

```ts
const savedSendData = ref<TextToImageProjectSendData>(...);
const sendData = ref<TextToImageProjectSendData>(...);
```

要求：

- `load()` 成功后同时设置保存快照和编辑副本；
- 使用稳定的选择键比较两个规范化集合，不能依赖数组偶然顺序；
- `dirty` 为真时标题区显示 warning 状态：“有未保存更改，尚不会发送给 LLM”；
- 无修改时保存按钮禁用；保存成功后以服务端响应同时更新两份状态；
- 保存失败保留编辑状态，允许重试；
- Project 切换、工作台关闭和页面切换前复用统一的“保存、放弃、取消”保护；
- 切换过程中不允许旧 Project 的迟到响应覆盖新 Project 状态。

三类条目统一使用可点击整行：

- 选中：`accent` 边框和背景、可见 check 图标、明确徽标；
- 未选中：普通边框和“未固定发送”辅助文字；
- 不能只用颜色表达，图标、文字和 `aria-checked` 必须同步；
- Lorebook 徽标为“固定发送”；
- 角色区标题改为“角色固定发送列表”；
- 服装徽标为“固定发送服装”；
- 每栏标题显示“已选 N / M”；
- 页面说明明确“启用分组负责自动扫描，本页负责无条件固定发送”。

### 5.2 分组启用态

在“当前启用角色分组”页面：

- 标题显示“已启用 N / M 个分组”；
- 启用卡片使用 `accent` 边框/背景、check 图标和“已启用”徽标；
- 未启用卡片显示“未启用”；
- 左侧树的分组节点增加可读的“启用”标识，保留现有图标但不只依赖小图标；
- 零启用组显示 warning：“正文不会自动注入角色，只生成场景内容”；
- “仅启用此组”在当前已经唯一启用时显示“当前唯一启用”并禁用；
- 请求时锁定目标组 ID，只有目标卡片显示 spinner 和“正在更新…”；
- 成功后以 API 返回状态更新，不用本地猜测；失败保持服务端原状态并通知；
- 连续点击和双击只提交一个启用更新请求。

### 5.3 跨组移动交互

- 按钮文案从“加入分组”改为“移动到分组”；
- 辅助说明写明“移动当前 JSON；来源不会保留这一份资料”；
- 动作类型从 `copy_to_group` 改为 `move_to_group`；
- 有未保存编辑时，移动前复用“保存、放弃、取消”保护；
- 前端提交时冻结来源 `groupId + characterId + visualId + updatedAt` 和目标 `groupId`；用户随后切换选择不能改变已发请求；
- 预检若发现目标相同内容副本、文件名冲突或 ID 冲突，确认 Dialog 展示最终行为；普通无冲突移动可直接提交；
- 成功后重新加载树，展开目标组和角色，选中 API 返回的目标 ref；
- 来源最后一份被移动时，来源角色节点自然消失；
- 成功通知区分“已移动”和“已合并目标中的相同资料”；
- 失败后来源选择、目标选择和未保存内容保持不变；
- 不乐观删除侧栏节点。

### 5.4 角色身份编辑

身份字段为：

- 中文名 `cnName`；
- 英文名 `enName`；
- 触发词 `triggerWords`。

UI 要求：

- 触发词标签改为“触发词（使用 | 分隔）”；
- 就地帮助写明“留空时正文扫描使用角色中英文名；不会自动写入输入框”；
- 输入时立即拒绝 `,`、`，` 和连续空项，保存前服务端再次校验；
- 展示规范化预览，例如 `艾莉希雅 | 爱莉 | Elysia`；
- 身份变化与普通视觉变化分别追踪；
- 保存身份时提示会同步的分组数和 JSON 数；
- 同时修改身份和视觉字段时必须作为一个事务提交，不能身份成功、当前视觉失败；
- LLM 修改预览继续锁定身份字段，不得借此改变名称或触发词。

## 6. 后端与 API 施工

### 6.1 集中触发词领域函数

建立唯一的触发词领域模块，供 codec、视觉库、旧 API、正文扫描和测试调用。建议公开：

```ts
type ParsedCharacterTriggers = {
    values: string[];
    canonical: string;
};

parsePipeCharacterTriggers(raw: string): ParsedCharacterTriggers;
buildEffectiveCharacterTriggers(character: CharacterVisualField): string[];
containsForbiddenTriggerSeparator(raw: string): boolean;
```

约束：

- `parsePipeCharacterTriggers()` 只允许 `.split("|")`，不得出现逗号兼容分支；
- 一次性迁移器使用独立、私有的 `parseLegacyCommaTriggersForMigration()`，不能被运行时导入；
- `buildEffectiveCharacterTriggers()` 仅在显式列表为空时回退中英文名；
- `normalizeVisualIdentity()` 只校正 `schema/characterId/visualId` 和触发词空白格式，不添加任何名称；
- 删除旧服务中重复的 `normalizeCharacterIdentity()` 追加逻辑，统一调用严格规范函数；
- API 错误必须包含角色、分组和文件的安全标识，不输出完整 JSON。

### 6.2 视觉移动 API

用新 API 替换复制入口：

```ts
type MoveCharacterVisualRequest = {
    projectRoot: string;
    sourceGroupId: string;
    sourceCharacterId: string;
    sourceVisualId: string;
    expectedUpdatedAt: string;
    targetGroupId: string;
    expectedPreviewRevision?: string;
};
```

建议路由：

- `GET character-library/visual.move-preview`：只读返回影响摘要；
- `POST character-library/visual.move`：执行事务并返回最终 ref、info、visual 和映射。

预检响应至少包含：

```ts
type MoveCharacterVisualPreview = {
    revision: string;
    source: CharacterVisualRef;
    targetGroupId: string;
    sourceWillLoseCharacter: boolean;
    sourceNeedsActiveFallback: boolean;
    targetCharacterExists: boolean;
    equivalentTargetRef: CharacterVisualRef | null;
    fileNameConflict: boolean;
    visualIdConflict: boolean;
    managedReferenceCount: number;
};
```

提交响应至少包含：

```ts
type MoveCharacterVisualResult = {
    mode: "moved" | "merged-equivalent";
    ref: CharacterVisualRef;
    info: CharacterVisualFileInfo;
    visual: CharacterVisualFile;
    sourceCharacterRemoved: boolean;
    updatedManagedReferenceCount: number;
};
```

所有 schema 使用 Zod `.strict()`；校验来源与目标不能相同；目标分组必须存在；来源 revision 或预检 revision 过期返回 `409`。

当前 `visual.copy` 在确认没有其它产品调用者后删除；不能留下 UI 不可见但仍可继续制造浅复制照片引用的公共入口。若仍有调用者，必须先迁移调用者，不能用长期兼容分支维持旧语义。

### 6.3 移动事务

不得使用“调用 `createCopy()` 成功后再调用 `deleteVisual()`”实现。正确顺序：

1. 获取 Project 级视觉库写锁并恢复未完成事务；
2. 读取来源/目标 manifest、来源原始字节、格式化视觉内容、分组清单和发送数据；
3. 校验 `expectedUpdatedAt` 和预检 revision；
4. 计算内容指纹、文件名、`visualId`、生效项和受管引用迁移计划；
5. 在 `.nbook/text-to-image/.txn/` 下创建受控事务目录和日志；
6. 备份来源/目标 manifest、相关视觉文件和 `.nbook/text-to-image-send-data.json`；
7. 无等价副本时先准备目标文件与目标 manifest；有等价副本时只准备 ref 合并；
8. 更新角色/服装固定发送引用中的 `groupId/visualId`；普通只存 `characterId` 的跟随引用保持不变；
9. 更新来源 manifest；来源无剩余视觉时删除空角色目录，仍有视觉时设置确定性 fallback；
10. 复读目标视觉、manifest 和发送数据，验证 ref 唯一、哈希、数量和照片引用；
11. 全部验证成功后提交事务并清理备份；
12. 任一步失败按日志恢复来源、目标和发送数据；下一次 `ensure()` 必须能恢复进程中断事务。

照片处理规则：

- 移动和等价合并都不调用 `removeRegisteredPhotos()`；
- 不复制照片二进制；
- 校验所有受控照片路径仍指向 Project 内允许位置；
- 等价副本合并后照片引用仍由目标 JSON 持有，不能因删除来源 JSON 删除资产。

### 6.4 角色身份事务

新增服务方法按 `characterId` 枚举所有分组和所有 manifest 中的视觉 JSON：

```ts
updateCharacterIdentity(projectRoot, {
    characterId,
    identity: {cnName, enName, triggerWords},
    selectedVisualPatch,
    expectedIdentityRevision,
    expectedSelectedUpdatedAt,
});
```

要求：

- 先严格解析并规范化 `triggerWords`；
- 计算全部相关视觉文件的身份 revision；
- revision 不一致返回 `409`，不覆盖并发修改；
- 在同一个 Project 写锁和事务内更新所有合法视觉 JSON；
- 当前选中视觉的其它修改与身份同步一起提交；
- 不改变任何视觉文件的 `visualId`、文件名、服装、照片和非身份字段；
- 损坏 JSON 导致无法安全同步时整个身份操作失败，并列出安全文件标识；不能只更新可解析文件造成进一步分叉；
- 成功后返回更新文件数、分组数、当前视觉新 revision 和规范化身份；
- 保存不含身份变化的普通视觉时只写当前 JSON，并保证身份字段与磁盘基线完全相同。

### 6.5 正文扫描修复

扫描顺序：

1. 读取已启用分组的当前生效视觉；
2. 对同一 `characterId` 保持现有分组优先级去重；
3. 使用严格 `|` 解析器获得显式触发词；显式为空才回退中英文名；
4. 中文按兼容子串规则匹配；英文按 NFKC + 不区分大小写匹配；
5. 记录每个角色实际命中的触发词；
6. 如果不同 `characterId` 被同一个规范化触发词命中，返回明确歧义错误，列出角色显示名和触发词，不进入 LLM；
7. 同一角色多个触发词命中只注入一次；用于诊断的 `matchedTrigger` 选择正文中最早出现者，位置相同取更长触发词，再按配置顺序稳定选择；
8. 固定发送角色继续按现有规则合并，并在请求 trace 中标记来源是 `project-send-data` 还是正文触发。

不要把英文逗号、中文逗号或正则“常见分隔符集合”重新加回运行时解析器。

## 8. 测试矩阵

### 8.1 触发词格式与迁移

- `艾莉希雅 | 爱莉 | Elysia` 解析为 3 项并规范化为相同格式；
- 首尾空格被清理；重复词按规范化值去重；
- `艾莉希雅, 爱莉`、`艾莉希雅，爱莉` 在迁移完成后的保存 API 中拒绝；
- `艾莉希雅 || 爱莉` 拒绝；
- 空触发词保存为空，扫描临时回退中英文名但不写回文件；
- 显式触发词非空时不再自动使用中英文名；
- 英文大小写和全角/兼容字符按规范匹配；
- 旧英文逗号、中文逗号和混合逗号只在一次性迁移测试中转换为 ` | `；
- 迁移二次运行不再改文件；
- 迁移中途写入失败、格式标记失败和进程中断均恢复；
- 损坏 JSON 保留且有警告，不被静默删除；
- 源码门禁确保运行时模块不存在 `.split(",")`、`.split("，")` 或宽松分隔正则。

### 8.2 保存副作用与身份一致性

- 手动删除角色名触发词后保存，角色名不会重新出现；
- 只修改外貌、身体、负面 Tag、服装或照片时，身份字段完全不变；
- 修改中文名不会累积旧中文名；
- 修改英文名不会偷偷加入显式触发词；
- 修改任一身份字段后，同角色跨分组、跨 JSON 版本全部同步；
- 同时修改身份和当前视觉时全部成功或全部回滚；
- 某一相关 JSON 损坏时身份保存整体失败；
- revision 过期返回 `409`，所有文件保持原值；
- `schema/characterId/visualId` 的必要校正保留，但没有其它业务字段被隐式追加。

### 8.3 正文扫描

- 零启用分组不扫描角色；
- 单个和多个启用分组按优先级选择；
- 同 `characterId` 跨组只选最高优先级当前视觉；
- 不同 `characterId` 同触发词命中返回歧义，不调用 LLM；
- 同一角色多个别名命中只注入一次；
- `matchedTrigger` 选择规则稳定；
- 固定发送角色无正文触发也会注入，并能在 trace 区分来源；
- 固定发送和扫描命中同角色时只保留固定选择版本。

### 8.4 跨组移动

- 来源最后一份视觉移动后，来源角色节点消失；
- 来源还有其它版本时只移除当前 `visualId`，fallback 生效项正确；
- 目标没有同角色时创建目录和 manifest；
- 目标已有同角色时合并版本且不覆盖；
- 目标存在等价内容时复用目标 ref，不生成第三份；
- 多个等价目标时预检报冲突；
- Windows 大小写文件名冲突安全改名；
- `visualId` 冲突生成新 ID 并更新内容与受管引用；
- 角色和服装固定发送引用同步更新；
- 普通仅 `characterId` 的跟随引用不被固定化；
- 移动后照片可读取，删除来源资料不会删除目标仍引用的照片；
- 来源/目标相同、目标不存在、来源过期和预检过期均拒绝；
- 目标写入、manifest、发送引用、来源更新、校验和清理每个故障点都能回滚；
- 重启后能恢复未完成事务；
- 双击移动只产生一次提交。

### 8.5 发送数据 UI

- 三栏选中行都有背景、边框、图标、文字和 ARIA 状态；
- 每栏数量准确；
- 勾选后立即显示未保存 warning；
- 未点击保存时后端读取仍是旧快照；
- 保存成功后 warning 消失且重载保持；
- 保存失败保留编辑选择；
- 页面切换和关闭时保存/放弃/取消均符合选择；
- Project 快速切换不会被旧响应覆盖；
- 文案准确说明角色是固定发送而不是启用扫描。

### 8.6 启用分组 UI

- 启用和未启用卡片在所有内置主题下均可区分；
- 状态不只依赖颜色；
- 标题数量和侧栏标识同步；
- 零启用组 warning 可见；
- “仅启用此组”成功、失败、唯一启用和双击状态正确；
- 更新期间只有目标卡片显示 pending；
- API 失败后 UI 回到服务端真实状态。

## 9. 验收标准

全部满足才能报告完成：

1. 发送数据页面能明确看出固定发送项、选中数量和未保存修改；只有服务端已保存选择进入下一次请求。
2. 页面明确区分“固定发送”和“启用分组自动扫描”，用户无需理解内部 API。
3. 启用角色分组在主列表和侧栏都有明显、非纯颜色标识；零、单个和多个启用状态准确。
4. 跨组操作不再复制当前视觉 JSON；来源最后一份被移动后旧分组不再显示该角色。
5. 目标已有相同资料时合并到已有 ref，不产生第三份；照片与发送数据引用保持有效。
6. 任何移动事务失败都不丢文件、不留下双份真相源、不破坏 manifest 或发送选择，并可在重启后恢复。
7. 新保存的 `triggerWords` 只允许 `|`，规范输出只使用 ` | `；英文逗号和中文逗号输入均被明确拒绝。
8. 历史逗号格式只通过一次性迁移转换；迁移完成后正常解析路径完全不支持逗号分隔。
9. 删除显式触发词后保存不会自动补角色名；修改任何非身份字段不会改变名称或触发词。
10. 空触发词只在运行时回退中英文名；显式非空列表不会附加未填写名称。
11. 同一角色全部视觉 JSON 的中文名、英文名和触发词保持一致；并发或损坏文件不会导致部分同步。
12. 英文触发匹配大小写稳定；不同角色同触发词时在调用 LLM 前返回可理解的歧义错误。
13. 聚焦测试、类型检查和差异检查记录完整命令与真实结果；浏览器或真实 Project 验收未执行时明确写“未执行”。
