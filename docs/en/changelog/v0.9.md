# 0.9.x Release Notes

This release line turned NeuroBook's AI assistant from a one-shot chat tool into a workflow that can draft, review and revise a chapter. It also added the bookshelf-first entry point, image attachments, account backup, an English documentation site and the first complete runtime and installation checks.

## 0.9.3-canary (limited canary, published) - 2026-08-07

> Git range: `v0.9.2-canary.20260805.125926Z.39d220b7..69313ad5ccc0e54203daeeebe69589f108fa3572`. Published tag: `v0.9.3-canary.20260807.175842Z.771ac42b`. This is a limited canary, not a stable release.

This round focuses on the failures that make a long-running Agent session hard to trust: stop-request feedback, session recovery, durable Job results and development cache ownership. It also brings the Windows-first Desktop Workbench spike into the main line.

### New

- Background Jobs now keep terminal state and complete results so finished tasks remain readable after a restart.
- The Windows-first Electron/Tauri Desktop Workbench spike now lives in the main line with shared title-bar, Activity Bar and Agent/IDE envelope contracts.

### Improved

- Source Dev defaults rebuildable cache data to `<checkout>/.agent/cache` while respecting an explicit Cache Root.
- The settings center uses a stacked layout and compact horizontally scrollable navigation on narrow screens.
- Retrieval uses a Git Bash-safe `rg --files -g 'index.md'` enumeration command.
- Clean runners generate Prisma/Nuxt artifacts first and use host temporary paths for cross-platform fixtures; the cover route cold-import budget is 30 seconds.

### Fixed

- Failed stop requests now produce user-visible feedback.
- A missing linked Agent Session no longer makes a valid primary Session look unavailable; automatic recovery does not loop forever after one failure.
- Job terminal state is durably committed before it is published; corrupt single-file history is quarantined and pending deliveries cannot be cleared early.

### Upgrade notes

- Back up the complete State Root and important Project Workspaces before migrating. New Job history lives under `<Workspace Root>/.nbook/agent/jobs/`; see the [migration guide](../../migrations/0.9.3-canary.md).
- Restart does not resume an old Workflow, and the full Workflow graph, step timeline and pending ask remain process-owned.
- The old checkout-root `cache/image-variants` directory is not migrated or deleted automatically.
- Real providers and complete Agent/Workflow browser acceptance remain known limits of this canary. Public Manager provenance, the release workflow, public assets and GHCR verification passed; signed installers and the final Desktop framework choice are outside this release.

## 0.9.2-canary - 2026-08-05

> Git range: `v0.9.1-canary.20260803.103354Z.13129ccc..v0.9.2-canary.20260805.125926Z.39d220b7`.

This release made Workflow waiting, answers, result projection and error handling traceable from the Composer to the Job center, while tightening Product, Manager, Desktop and Agent configuration boundaries.

### New

- Workflow pending Composer cards now keep answers separate for each run.
- Workflow results, state visuals, Job details and usage projections are visible in the task center and chat surfaces.
- Windows-first Desktop Envelope, Product Runtime Contract and installation-state checks entered a verifiable spike.

### Improved

- Composer submission now distinguishes ordinary Enter, newline, IME composition and explicit submit shortcuts.
- Cancellation, errors, partial output and retry branches use separate public projections instead of one generic error path.
- Profile/Variable authoring, Product schemas, OpenCode retries and release baselines received tighter boundary checks.

### Fixed

- Fixed blank Profile details after switching, missed dynamic `outputSchema` result binding and duplicate Workflow resume.
- Fixed several Product archive, Manager installation, Portable lifecycle and Session Store lease contract edges.

### Upgrade notes

- This is a canary. Back up the complete `data/` or State Root and test startup, migration and Agent compilation with a disposable Project first.
- Desktop work remains a spike; it is not a signed installer, updater or final cross-platform package.

## 0.9.0-canary - 2026-08-02

### New

- Open NeuroBook at a bookshelf where you can create, open, delete and organize projects before entering a novel.
- Attach images by dragging them into chat, pasting from the clipboard or choosing files. Retry failed uploads, remove attachments and inspect the original image.
- Run multi-step writing workflows such as draft-review-revise, cross-chapter consistency checks, book breakdown and character interviews. Workflows can run in the background and ask for approval before starting.
- Configure each writing assistant from a searchable split settings view, with compile status, overrides, unsaved changes and the default assistant visible.
- Use the NeuroBook account and backup flow, and read the new English documentation site.
- Open the context inspector to see what a request contains and why a prompt-cache entry did or did not hit.

### Improved

- Reduced the Windows runtime image from roughly 30,000 files and 1.2 GB to about 3,231 files and 127 MiB while retaining local profile compilation, database support and image processing.
- Reworked profile and variable compilation caches, temporary staging cleanup, installation recovery and process shutdown so interrupted operations can be resumed or rolled back.
- Added a stable branch switcher for regenerated assistant replies and clarified that “fork” starts an empty conversation branch.
- Updated llmlint to 360 rules with review buckets, density checks and safer dependency reuse.

### Fixed

- Restored missing assistant sessions without silently creating a new session or losing the current project selection.
- Fixed Windows portable shutdown, source-development process cleanup, profile compilation failures and several stale installation and migration states.
- Fixed image-size limits and several context, cache and model-selection reporting errors.

### Upgrade notes

- This is a canary build. Test it with a disposable project first and keep a backup of the whole `data/` directory before upgrading.
- Remote text detection sends cache misses to the configured external service. Do not run it when text must remain on the local machine.
- The account backup contains the complete local instance, including API keys stored in configuration.
