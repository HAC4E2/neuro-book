# 章节正文插图整体重 Roll 设计

日期：2026-07-15

状态：书面规格待用户复核

## 1. 背景

正文生图当前会读取已保存章节，依次执行角色识别、正文 LLM 提示词生成、插图定位和 Prompt 编译，最后把结构化 `<text-to-image-prompt>` 占位符写入章节。用户点击占位符后，服务端 NovelAI 队列生成图片，并把占位符替换为标准 Markdown 图片。图片文件与资产元数据独立保存在 Project Workspace 和 Project SQLite 中，可在历史图片分页查看。

当前再次点击“正文生图”会基于包含旧占位符或旧插图的正文继续生成，容易重复规划插图。本设计把该按钮统一定义为“重新规划当前章节全部正文插图”：首次执行时正常生成，再次执行时事务式替换旧规划。

## 2. 目标

1. 每次点击“正文生图”都基于不含 NeuroBook 旧正文插图的纯正文重新运行完整 Agent 和 LLM 链路。
2. 仅移除当前章节所属的正文生图图片引用和所有正文生图占位符，保留手动图片、外链图片及其他章节资产。
3. 旧图片文件、资产记录和历史分页记录始终保留。
4. 只有新插图规划有效且章节版本未变化时，才一次性写入“移除旧规划后的正文 + 新占位符”。
5. Agent、LLM、定位或并发校验失败时，正文保持原样。

## 3. 非目标

- 不删除或覆盖任何历史图片资产。
- 不自动重新请求 NovelAI 生成所有新图片；本轮仍沿用正文占位符按钮逐图入队的现有交互。
- 不修改正文生图世界书的 `<image>...</image>` 输出合同。
- 不取消已经进入 NovelAI 队列的旧任务。
- 不清理用户手动插入的普通 Markdown 图片。
- 不新增独立的章节重 Roll 队列或数据库模型。
- 不自动执行浏览器交互验收。

## 4. 核心语义

“正文生图”不再表示向章节追加一批插图，而表示重新计算当前章节的完整插图规划。

- 章节没有旧插图时，清理结果与原文相同，行为等同首次生成。
- 章节已有旧插图时，Agent 和 LLM 接收清理后的正文副本。
- 至少产生一个有效新位置时，服务端提交整体替换。
- 没有有效新位置时，服务端不提交清理结果，旧插图继续保留。

## 5. 受管内容识别

### 5.1 占位符

所有结构合法的 `<text-to-image-prompt>` 块都属于当前章节正文生图规划。重 Roll 时从工作副本中移除这些块。

### 5.2 已生成图片

服务端从 `TextToImageAsset` 查询当前 `projectPath + chapterPath` 所属的正文生图资产，得到允许移除的 Project-relative 路径集合。Markdown 清理器只移除目标地址位于该集合中的标准 Markdown 图片。

识别不能只依赖 `assets/text-to-image/` 路径前缀或图片 alt 文本。这样可以保留用户手动引用的图片、从其他章节复制来的图片以及普通外链图片。

### 5.3 资产保留

清理只修改章节 Markdown 引用，不调用资产删除接口，不修改 `TextToImageAsset`，也不删除 `assets/text-to-image/**` 文件。旧图片继续显示在历史图片分页中。

## 6. 组件边界

### 6.1 `TextToImageAssetService`

新增按当前章节查询正文生图资产相对路径的只读能力。该方法不返回文件绝对路径，也不承担 Markdown 修改。

### 6.2 `shared/text-to-image-markdown.ts`

新增纯函数清理合同，输入章节 Markdown 与允许移除的资产路径集合，输出：

- `markdown`：清理后的正文；
- `removedPromptCount`：移除的占位符数量；
- `removedImageCount`：移除的已生成图片数量。

该函数只处理 NeuroBook 明确管理的块，不改写其他 Markdown 内容。清理块后只收敛由清理产生的多余空行，不重新格式化整篇章节。

### 6.3 `TextToImageBodyPromptService`

正文生图编排顺序调整为：

```text
读取原章节快照与 hash
  -> 查询当前章节正文生图资产路径
  -> 在内存中清理旧图片引用和旧占位符
  -> 用清理后的正文识别相关角色
  -> 用清理后的正文请求正文 LLM
  -> 用清理后的正文建立段落和运行定位 Agent
  -> 编译新 Prompt
  -> 事务式提交整体插图规划
```

角色识别、正文 LLM 和定位 Agent 必须使用同一份清理后正文，避免段落 ID、偏移和语义上下文分叉。

### 6.4 `TextToImageChapterService`

新增或收敛为显式的“替换章节插图规划”写入方法。该方法在章节文件锁内：

1. 读取当前正文；
2. 校验当前正文 hash 仍等于请求开始时的原始 hash；
3. 以经过验证的清理后正文为写入基底；
4. 按清理后正文的段落偏移插入新占位符；
5. 通过 tracked workspace write 一次写回。

清理旧引用与插入新占位符不能拆成两次文件写入。

## 7. API 与前端

继续复用 `POST /api/text-to-image/body-prompts`，不增加第二套重 Roll 接口。接口语义直接变为“重新规划当前章节正文插图”。

成功响应在现有字段之外返回：

- `removedImages`
- `removedPrompts`
- `inserted`
- `skipped`
- `warnings`

前端继续使用同一个“正文生图”按钮。成功时根据统计显示“本章插图已重新规划”，并报告移除和新增数量；没有有效新位置时显示警告且不刷新正文。

## 8. 事务与并发

Agent 和 LLM 调用期间不持有章节文件锁，避免长时间阻塞作者编辑。写入阶段继续使用乐观并发：原始 hash 不一致时返回 `409 TEXT_TO_IMAGE_CHAPTER_CONFLICT`，不修改正文。

旧的 queued 或 running 正文图片任务不强制取消：

- 如果它在新规划提交后完成，旧占位符已不存在，资产进入历史，`sourceInsertStatus` 变为 `missing`，不会重新插回正文。
- 如果它在 Agent 运行期间改写了章节，原始 hash 校验失败，本次重 Roll 不写文件，用户基于最新正文重新执行。

## 9. 失败语义

- LLM 未返回有效 `<image>`：返回警告，不写正文。
- 定位结果全部无效或低于置信度门槛：返回警告，不写正文。
- 角色识别、LLM、定位 Agent 或 Prompt 编译抛错：请求失败，不写正文。
- 章节 hash 冲突：返回 409，不写正文。
- 资产路径查询失败：请求失败，不尝试按宽泛规则清理图片。
- 至少一个新位置有效但部分位置被跳过：提交有效的新规划，并通过 `skipped` 和 `warnings` 告知用户。

## 10. 测试设计

### 10.1 Markdown 合同

- 移除所有合法正文生图占位符。
- 只移除目标路径集合中的 Markdown 图片。
- 保留手动图片、外链图片和不属于当前章节的资产。
- 同时清理多个图片和占位符，并返回准确计数。
- 清理后不破坏相邻正文、代码块或其他 Markdown 结构。

### 10.2 资产查询

- 只返回当前 Project、当前章节的正文生图资产路径。
- 不返回其他章节、手动任务或角色任务资产。
- 查询不修改数据库和图片文件。

### 10.3 章节事务

- 成功时旧引用与新占位符在一次 tracked write 中完成替换。
- 过期 hash 拒绝写入并保留原文。
- 段落文本或偏移不匹配时跳过对应位置，不追加到章节末尾。

### 10.4 编排服务

- 角色识别、正文 LLM 和定位阶段接收同一份清理后正文。
- 首次生成在没有旧受管内容时保持现有行为。
- LLM 无有效 Prompt 或定位全部无效时，不清除旧插图。
- 成功响应包含准确的移除与插入统计。

### 10.5 回归验证

- 运行 Markdown、asset、chapter、body prompt 相关聚焦 Vitest。
- 运行项目类型检查；若存在与本任务无关的既有失败，单独记录而不误报本功能通过全仓门禁。
- 按项目规则不自动执行浏览器验证，完成后可由用户决定是否授权。

## 11. 验收标准

1. 第一次点击“正文生图”正常插入新图片占位符。
2. 章节已有正文生图图片或占位符时再次点击，Agent 接收不含旧受管内容的正文。
3. 成功后旧受管引用全部消失，只留下新规划占位符。
4. 手动图片、外链图片和其他章节资产引用保持不变。
5. 历史图片分页仍能查看所有旧图片。
6. 任何调用失败或章节冲突都不会让旧插图从正文中消失。
7. 不出现无锚点图片追加到章节末尾的回归。
