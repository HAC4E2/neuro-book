# 现状与参照

nb-story 第一版界面设计的起点：现有的数据、现有的开发用查看器（w00005 t28）、要沿用或放弃的机制，以及外部参照。设计依据是 w00005 工作树里的提案 `docs/proposals/novel-story-app.md`（accepted，2026-10-13；随 w00005 落到 master 之前，只在 `.worktree/w00005-novel-understanding-spike/` 里）。

## 数据：第一本书有什么

w00005 t34 用定型管线自动抽取的前 100 章（`evidences/run-med-100/dataset-v9.json`，约 5.4 MB，含原文），没有人工修改。

| 类别 | 条数 | 界面上对应什么 |
| --- | ---: | --- |
| 原文 | 100 章 | 原文阅读器；每段有“章.段”编号 |
| 段落块概括 | 455 | 原文里的分段小结，带故事时间 |
| 对象 | 176（人物 18、化身和代号 14、物品 37、任务 35、概念 29、地点 24、组织 8、其他 11） | 名册、人物卡 |
| 称呼出现处 | 9,615 | 原文里名字带底色；人物卡的称呼表（苏天晴有 45 个称呼） |
| 说法 | 1,739 | 人物卡里“关于他的说法”、搜索 |
| 秘密 | 11 | 秘密矩阵 |
| 知情记录 | 1,356 | 秘密矩阵的格子、人物卡里“他知道什么” |
| 情节 | 247 | 情节页、人物卡里“参与的情节” |
| 时间点 | 184 | 时间线 |
| 数值和进度的变动 | 186 | 数值页（神典石余额、道具、任务进度） |
| 悬念 | 257（读到第 100 章时 227 条未解或部分解答） | 悬念页 |

所有记录都带出处（“章.段”）和出现位置，按“读到哪里”过滤后不含后文。

图是自动抽取的，有错：对象分类粗（南嘉鱼本人被归成“化身”，舍友、导购员和主角并列在人物里）；称呼张冠李戴（南嘉鱼的称呼里混进了“天晴”）；身份合并有错（“完美使魔是心月狐的替身”被当成同一人）。界面要让人随手回原文核对，不能把图包装成定论。

## 现有查看器（t28）

开发者核对设计用的单个离线页面，前 100 章版本是 w00005 t34 的 `evidences/viewer-v9-100ch.html`（2.9 MB）。完整截图集在本地 `.local/agent/works/w00024-nb-story/tasks/t01-ui-design/shots/t28-100ch/`，评审板里放了五张。

| 页签 | 现在的样子 | 问题 |
| --- | --- | --- |
| 原文 | 顶部 100 个章号排成一行，正文里夹着段落块概括（蓝底块），名字带底色，段尾是记录条数，点段落右侧列出记录 | 章号一行放不下；概括块打断阅读；右侧空白时占一半宽度 |
| 对象 | 左侧名册按首次出现排序，右侧对象详情：称呼表、身份、出场、说法、知情、情节 | 路人和主角混在一起；标签是长描述（“重生后成为金毛狐女的苏天晴”）；详情是一长页 |
| 说法 | 1,739 条，可按章、大类、断言类型、来源筛 | 开发用；普通用户不会直接逛说法 |
| 秘密与知情 | 每个秘密一张表：谁、状态、位置、怎么知道的 | 11 张表要一张张往下翻，看不出“某个人知道哪些” |
| 状态 | 186 条变动按“对象的某项”分组成卡片 | 神典石这类数值没有余额曲线；任务进度和数值混在一起；一屏只看几笔 |
| 疑问 | 未解和部分解答 227 条一长列 | 太多，重要的淹没在琐碎的里；看不出“这一章新提出、新解答了什么” |
| 时间线、情节 | 按故事先后或按章的列表 | 尚可，缺筛选 |
| 说明与统计 | 草稿写了多少条、程序生成了多少项 | 开发核对用 |

另外：处处显示记录编号（s3-19、q1-1、l1-1）；没有搜索；没有链接地址，刷新就回到第一页；整本书和整张图塞进一个页面，书再长就打不开。

## 沿用的机制：防什么、还要不要

| 机制 | 防什么 | 建议 |
| --- | --- | --- |
| 读到哪里（选章加拖动条） | 剧透：后文的称呼、身份、知情、数值提前出现 | 保留，放在顶栏常驻；过滤改由服务做 |
| 段落上的记录条数，点段落看记录 | 图上的话没有依据 | 保留 |
| 名字带底色、可点开 | 认不出化名和代号 | 保留 |
| “明说、推断、角色的说法”标签 | 把推断或角色的一面之词当事实 | 保留 |
| 段落块概括夹在原文里 | 读得慢：可以先扫概括 | 改成开关，默认收起 |
| 记录编号 | 开发对照数据用 | 默认不显示，悬停或调试时显示 |
| 说明与统计页 | 核对程序生成了什么 | 产品里不要；“关于这本书”只留来源和抽取说明 |
| 秘密表上“没有记录不等于不知道”的说明 | 把没记录误读成“不知道” | 保留，改成矩阵里“没有记录”格子的图例 |

## 外部参照

- **Kindle 的 X-Ray**：按读到的位置列出这一页、这一章、整本书里的人物和术语，各带出现分布，只给读到之前的信息。和本产品“读到哪里”的做法相同，是“边读边查”最接近的参照。
- **小说和剧集的维基**：人物页、关系、时间线齐全，但不分阅读进度，剧透是常见抱怨，靠人工加剧透警告。本产品的差别正在于按位置过滤。
- **NeuroBook 和开发者面板**：同用 Vue 3 加 nb-ui；开发者面板（`packages/dev-panel`）是“本机服务加登录链接加网页”的先例，左侧导航、右侧详情的布局也可以参照。以后嵌进 NeuroBook 时，查看器和问答是工作台里的视图。
