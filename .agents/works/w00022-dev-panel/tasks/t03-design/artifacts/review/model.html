领域模型：开发者项目面板（第二版）

2026-10-12，按开发者对第一版的意见重写，七件事开发者已确认（第 2 件改为面板能任意写仓库）。文字以 .agents/works/w00022-dev-panel/tasks/t03-design/domain-model.md 为准；这一页只把图画出来。

和第一版的区别
  1. 去掉持久的“参与”。会话与 Task 之间只有租约：会话在某个 Task 上做事时临时取得，会话结束或久不活动就失效，不入库。
  2. 项目数据里没有任何东西指向会话。Task 的状态、产物、提问、答复、证据都持久化，任何会话都能读。
  3. 取消本地 Work。Work 与 Task 的记录只放一处：主工作区 master 的 .agents/works/；实现分支只带代码、Spec 与文档的改动。
  4. 区分面板管理的会话（在 herdr 里，答复后能通知回去）和外部会话（不能通知，但能读到答复）。

一个开发流程

sequenceDiagram
    actor Dev as 开发者
    participant S as 会话（任何 Agent）
    participant CLI as 命令行 nbdev
    participant Repo as 项目数据（master 的 .agents/works）
    participant Panel as 面板
    participant H as herdr

    Dev->>S: 在任何终端里说“建一个设置界面的 Work，先做调研”
    S->>CLI: work new settings-ui；task new research
    CLI->>Repo: 领号，写 Work 与 Task 记录，提交
    CLI-->>CLI: 给这个会话取得 t01 的租约
    S->>CLI: artifact publish（含 3 个提问）
    CLI->>Repo: 写产物与提问，提交；提问记下提问者租约
    Panel->>Repo: 读到新产物与未答提问
    Panel-->>Dev: 收件箱：3 个待答
    Dev->>Panel: 在产物上作答
    Panel->>Repo: 写答复，提交
    alt 提问者租约有效，且是面板管理的会话
        Panel->>H: agent.prompt（followup 或 steer）：一行指针
        H->>S: 投递
    else 租约失效，或是外部会话
        Panel-->>Dev: 答复已保存；没有可通知的会话
    end
    S->>CLI: answers t01（任何会话都能读）
    S->>Repo: 把决定写进 Task 记录，改 Task 状态，提交

七件事（2026-10-12 已确认）

#问题决定
1Work 与 Task 的记录放哪里只放主工作区 master 的 .agents/works/，实现分支不再带记录；会话在任何 worktree 里干活，都在 master 上路径限定提交记录。备选：单独一个记录分支。已有长期分支的记录迁移另排一个 Task
2面板能不能写仓库能，先不限制写什么（开发者改了推荐：原推荐只写新建 Work 与 Task、答复三类）
3答复入不入库入库，文件形式，只追加
4证据的边界入库：结论文字、不可重现的测量数值、少量精选截图（单张约 300 KB 内、每个 Task 约 5 MB 内）；本地：完整截图集、日志、测试原始输出
5取消本地 Work规则改回只有一类 Work；.local/agent/ 只放能重新生成的运行时与原始输出
6Task 状态的取值计划中、进行中、已完成、已搁置，写在 frontmatter；“等开发者”现算（有未答提问）
7租约何时失效会话在 herdr 里消失即失效；外部或久不活动的 24 小时没有 Task 相关操作即失效；不入库
