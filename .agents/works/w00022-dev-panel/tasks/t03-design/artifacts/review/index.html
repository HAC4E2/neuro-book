说明第二轮发现的需求问题（会话为主）

herdr 只用了 agent list、agent get、agent read、pane list。下面先列拿得到的，再列拿不到的。

拿得到：每个 Agent 的种类（claude、omp）、状态（idle、working；枚举里还有 blocked、done、unknown）、工作目录与前台进程的目录、pane、tab、workspace 的 id、终端标题、Claude 的会话 id 或 omp 会话文件路径、是否聚焦、状态变化序号；pane 列表还包括不是 Agent 的终端（例如 :4217 开发服务就在 w1:pJ 里，第一轮查不到它的归属）；终端最近若干行的文字。

  1. 1
    会话属于哪个 Work、Task，herdr 不知道。7 个本仓库会话的工作目录都是仓库根；终端标题会过时（w1:p16 标题是“W00017 Workbench 组件重构”，在做 w00022；w1:pK 标题是“w00015 status check”，在做 w00005 t34）。稿子里的关联是读终端底部状态行里的路径、或产物路径里的会话 id 推出来的。要可靠，得让会话自己登记（例如 nbdev 写绑定，或 herdr 的 pane report-metadata，未验证）。
  2. 2
    “在等你”拿不到。herdr 的 blocked 只覆盖权限确认这类等输入，现在一个都没有；“问完问题停下来”在 herdr 眼里就是 idle。稿子里的 3 条“会话在等你”是读最后几行推断的。要么 Agent 显式登记“等开发者”，要么接受推断。
  3. 3
    输入框里没发出的话。w1:pB、w1:pQ 的输入框里各有一句开发者打了没发的话；herdr 读不出输入框的状态，agent prompt 发的字会接在后面一起提交。面板要么从画面识别并提示，要么需要 herdr 提供“输入框是否为空”或清空的能力。
  4. 4
    “它空闲时再发”要面板自己排队。herdr 的 agent prompt 在会话 working 时照样提交（Claude Code 排到这一轮后），blocked 时拒绝；它不跟踪轮次。排队要面板后端常驻、用 agent wait --until idle 再发，期间开发者也可能在终端里打字。“面板是否常驻”因此和这条绑在一起。
  5. 5
    子代理和非交互的 omp 看不见。主 Agent 派的后台子代理不是 herdr Agent；omp -p 跑的审查（t79 那个）是进程，不是会话。它们只能经 ps 与产物目录看到。
  6. 6
    会话里问、会话里答的问题到不了面板。t79 的会话用 Claude 的提问框问了“横排标志用哪种颜色”并在终端里答了；这类问题与答案不在任何产物上，收件箱和产物页都看不到。
  7. 7
    谁问的问题，靠路径推。通知小窗要知道“问这个问题的会话”；t80 的问题是从日志与报告路径里的会话 id（d02974de）推出来的。问题挂上产物时要记下提问的会话。
  8. 8
    别的仓库的会话也在列表里。w1:pY 在 stellaris-mcp；omp 的 w1:pV 在 /tmp 做系统升级。面板按工作目录过滤，或单列“别的仓库”。
  9. 9
    编号又差点撞上。w00017 主线 15:12 新建了 t82、t83（README 未提交）；第一轮命令行稿里“示例：领到 t82”现在会和真的 t82 撞号。这次两个会话都跳过了只在分支上的 t80、t81，但靠的是人记得。

说明第一轮发现的需求问题

取真实数据时碰到的，交主 Agent 核实后并入需求分析或另建 Task。

  1. 1
    “进行中”判不准。第一版不解析 Task 状态，只能按“近 7 天有提交、有未提交改动或有进程”近似：已完成待合入的 t81 照样算进行中，停了 10 天的 w00019 因主工作区有未提交改动也算。
  2. 2
    checkout 归属靠猜。w00017-t80-* 能从名字推断；w00017 主线 checkout 同时承载 t78、t79，只能从提交标题的 (t79) 推断；审查 checkout 是分离头，没有分支名。要 worktree new 登记归属，现有 11 个要补登记。
  3. 3
    “相对主线”的主线不唯一。t80、t81 的基线是 w00017 主线（refactor/w00017-runtime-foundation），它自己又对 master 领先 397、落后 7。每个 checkout 要记下基线分支。
  4. 4
    “没答复的讲解页”无从判断。现有评审板（t80 的、本页）既没有表单，也没有声明“等不等答复、几个待定”。页面要有这份声明（例如 page publish 登记，或页面里的元数据）。
  5. 5
    进程只能部分归属。开发服务 :4217 从终端 pts/8 起，输出不落盘、查不到哪个会话；omp 交互会话的工作目录是 /tmp；:4317 的日志在另一个 Claude 会话的临时目录。只有经 dev start 起的才有登记，其余只能标“归属不明”。
  6. 6
    审查报告还在临时目录。t80 的 omp 审查是 t02 之前起的，报告与会话在会话临时目录；面板要按条目标“改／不改／要讨论”，条目编号（C1…）得稳定，标记写进 answers/，报告原文只追加。
  7. 7
    截图报告里是旧的绝对路径。t80 各 shots/**/report.json 的 file 仍指向搬迁前的 .local/design-review/…；面板要按 report.json 所在目录找图，或 lab:shot 改写成相对路径。
  8. 8
    task new 把 README 写到哪。w00017 的进度在实现分支维护，主工作区只是占号副本；命令行要知道每个 Work 的执行位置，现在只写在 Work README 的文字里。
  9. 9
    “已读”存在哪没定。答案文件只追加，标为已读要另存一份（稿子里用 answers/.acks.jsonl）。
  10. 10
    Work 级的讲解页。.local/agent/works/w00017…/review/2026-09-30-platform-review.html 挂在 Work 下、不属于任何 Task，索引与“等你处理”都要认这一层。
  11. 11
    运行产物写进了入库目录。w00005 t34 的抽取日志写在 evidences/run-med-100.log（t02 之前的分支），按新规则应在 .local/agent/…/logs/。
