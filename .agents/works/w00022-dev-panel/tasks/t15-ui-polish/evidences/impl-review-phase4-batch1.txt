## 发现

### 1. 重要：刚答完（或别处答了）的题点“改答”，控件是空的；只加说明再交会丢取值

- 位置：`packages/dev-panel/src/web/parts/AnswerForm.vue:39-50`（`reset` 只给 `groups.answered` 预填）、`:56-58`（`startEdit` 不预填）、`:97-101`（只写说明时按 `values[id]` 带取值）；`packages/dev-panel/src/web/pages/ArtifactPage.vue:96-98`（先 `resetKey += 1` 再 `artifact.reload()`）。
- 场景：在待答里答了题 A、提交成功。父组件把 `resetKey` 加一，`reset()` 在下一次渲染前运行，此时 `props.questions` 仍是提交前的数据（`useResource.reload()` 保留旧数据，见 `host/panel-data.ts` 的 `restart(true)`），A 还在待答组，`reset` 把 `values` 换成“旧的已答组”的预填，A 的取值被清掉。重取回来后 A 进了“已答”，但 `values.A` 是 `undefined`。开发者此时点 A 的“改答”：`QuestionControl` 收到 `undefined`，单选、多选、确认都显示成没选，不是现在的答案。若他只点“加说明”写一句理由、不碰选项：`chosen` 因说明非空收进 A，`problems` 因 `!touched && state.answer` 跳过校验，`submit` 写 `answer.A = undefined`，`JSON.stringify` 把这个键丢掉。只交这一题时服务端回 `invalid_answer`（“答复里没有任何题的取值”）；和别的题一起交时，答复文件里 A 只有说明、没有取值，与第 99 行注释“这道题仍有取值”的意图相反。推送带来的“别处答了”（`answers record` 代录、另一个标签页）同样不会预填。
- 依据：从代码推断（没有挂载 SFC 的测试环境；验收里的“改答”是对加载时就已答的 uxq 题做的，没有覆盖提交后改答）。
- 建议：预填不要依赖 `reset` 时刻的题表。最小改法是在 `startEdit(state)` 里，这道题没 `touched` 时把 `values[id]` 设成 `state.answer?.value`（`cancelEdit` 已经这样做）；`submit` 里只写说明、没改取值的题直接取 `state.answer.value`，不读 `values`。`reset` 可以只清空本地状态，不再预填。

### 2. 建议：多选题空白的修法对症，但根在 nb-ui `FormCheckbox`；静态测试挡不住 `:class` 写法，计划要求的“交 nb-ui”一笔没有落下

- 位置：`packages/nb-ui/src/components/form/FormCheckbox.vue:53-67`（`<label>` 没有 `relative`，里面的 `<input class="peer sr-only">` 是绝对定位）；`packages/dev-panel/tests/web-scroll-containers.test.ts:23`（只扫静态 `class="..."`）；`.agents/works/w00022-dev-panel/followups.md`（没有 nb-ui 这一条）。
- 场景与判断：
  - 修法对症。`sr-only` input 的包含块落在滚动容器之外时，`main` 的滚动挪不动它，浏览器为了把聚焦的 input 滚进视野去滚外面 `overflow: hidden` 的格子；滚动容器带 `relative` 后，包含块回到滚动容器内。产物页宽屏时包含块是侧栏 `aside`（`relative`、自己滚），窄屏时是不滚的 `aside`，再往外是页面根（`relative`、滚），都对。dev-panel 里用到复选组的只有 `QuestionControl`，其余 `sr-only` 是不可聚焦的 `span`（`LeaseChip`、`TruncatedText`），没有别的受害点。要注意的是铺满页面下 `main` 本身是 `relative overflow-hidden`：铺满页面里任何自己开滚动却漏了 `relative` 的容器，聚焦时被滚走的会是 `main`，所以这条约定在铺满页面上更要紧。
  - 测试：把 `ArtifactPage.vue` 侧栏的 `relative` 去掉，测试失败、报出这一处（实测，在 `/dev/shm` 的副本上）；把 `lg:overflow-y-auto` 挪进 `:class="{...}"`，测试照样通过（实测）。scoped `<style>` 里写的 `overflow: auto` 与 nb-ui 组件内部的滚动区也扫不到。它是约定检查，不只是数 class，但能挡住的只有“静态 class 写法”这一种回归。
  - 更根本的修法在 nb-ui：`FormCheckbox` 的 `<label>` 加 `relative`（或 input 改 `clip` 而不绝对定位），input 的包含块就是它自己的 label，任何宿主都不再踩这个坑。计划写了“nb-ui 侧的同类风险记一笔，交 nb-ui”，后续清单里没有这一条。
- 依据：根因与覆盖面从代码推断；测试的两种变体为实测。
- 建议：后续清单补一条交 nb-ui：`FormCheckbox` 的 label 加 `relative`，并在 nb-ui 的组件测试里钉住，同时查 nb-ui 里其它用 `sr-only` 可聚焦元素的组件（`Dialog`、`QuickInput`、`FormField` 也用了 `sr-only`）。dev-panel 的测试注释里写明只覆盖静态 `class`，或把 `:class` 里的对象键与字符串字面量也纳入扫描；不必为此加浏览器测试。

### 补充第 1 条
