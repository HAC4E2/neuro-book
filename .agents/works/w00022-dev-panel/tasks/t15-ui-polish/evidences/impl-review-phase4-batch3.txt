## 发现

### 1. 重要：观看时字号只按宽度算，框高固定之后终端下半屏被裁，最新的几行默认看不到

- 位置：`packages/dev-panel/src/web/parts/TerminalView.vue:49`（`watchFontSize`）、`:226`（`frameBox`：`min-h-64 flex-1 overflow-auto`）。
- 场景：改版前观看时框高随行数、整页滚动，整屏都能看到；现在框高由铺满布局定死，字号却只按 `clientWidth` 与列数缩放，pane 的行数乘行高超过框高时，下面的行落在框外、要在框里往下滚才看得到，而框的滚动位置停在顶上。herdr 里左右分开的 pane（窄而高，例如 90×45）在 1440×900 下就会这样：字号按宽度取到 13，45 行约 700px，框只有约 460px。看 Claude 时被裁掉的正是输入框与状态行，看开发服务日志时被裁掉的是最新输出。
- 依据：实测（截图）。`final/b3-1440-watch.png`、`final/b3-1000-watch.png` 的终端框右侧是原生竖向滚动条，滑块约占轨道七成；`final/b3-1440-pane-history.png` 里 cat 的 pane 回滚 361 行、视口 40 行，框里只显示到第 377 行，后面二十多行在框下方。验收脚本没有检查“终端最后一行在视口内”。
- 建议：观看字号取宽、高两个方向能放下的较小值（高度用 `frameBox` 的内容高除以行数与行高比），放不下 5px 时再让框滚动并把滚动位置贴底；验收加一条“观看时终端最后一行在视口内”，用窄而高的假 pane。

### 2. 重要：详情列高度不够时终端框溢出，后面的输入区、说明行盖在终端最后几行上

- 位置：`packages/dev-panel/src/web/parts/TerminalView.vue:206`（根 `section` 是 `min-h-0 flex-1`，没有 `overflow-hidden`）、`:226`（`frameBox` 的 `min-h-64`）；`packages/dev-panel/src/web/parts/SessionConsole.vue:72`（贴底输入区 `shrink-0`）；`packages/dev-panel/src/web/pages/SessionsPage.vue:298`、`:314`（“更早的输出”面板与只读说明行）。

- 依据：实测（截图）+ 从代码推断。`final/b3-1440-pane-history.png` 底部放大后，“只读观看不写审计。要在这一格里操作，回 herdr。”压在第 377 行上，两行文字重叠；Agent 会话在矮视口下的遮挡从布局推断，验收只在 900 与 800 高下截图。
- 建议：`TerminalView` 根加 `overflow-hidden`、`frameBox` 去掉 `min-h-64`，最小高度放到详情列上并让详情列在放不下时自己竖向滚动（这样量列数量的就是看得见的框）；验收补一档矮视口（例如 1366×650）的观看、接管与“更早的输出”截图。

### 5. 重要：herdr 认出 Agent 但没有会话键的 pane 在左列表里消失，前后端对它的分类也不一致

### 7. 建议：Claude 会话文件末尾一段里只有一条大记录时标题读成 null，列表标题会来回跳

- 位置：`packages/dev-panel/src/server/session-titles.ts:18`、`:19`（注释“末尾一段里一定有最新的”与 `CLAUDE_TAIL_BYTES`）、`:180`（Claude 分支把这次读的结果按大小与修改时间缓存，读不到就缓存 null）。
- 场景：Claude Code 的一行记录可以超过 256KB（读截图时的 base64 图片、大文件的工具结果，这个仓库的验收经常读截图）。这样的行写进去之后，末尾 256KB 里没有任何标题行，`titleOf` 回 null，列表与详情头从“会话页重做”退回租约的 Task 或短号，直到下一次写标题行又变回来。读不出时的降级本身是对的，问题是注释的断言不成立、标题会闪。
- 依据：实测。`/dev/shm` 里造一份会话文件：先写一行 `ai-title`，读到“会话页重做”；再追加一行 300KB 的图片记录，同一个 `titleOf` 回 null。
- 建议：按会话记住上一次读到的标题，末尾一段里没有标题行时沿用它（文件变短或换了才作废）；或者没找到时再往前读一段、设总上限。把注释改成实际的保证。

### 8. 建议：找不到会话文件时没有负缓存，每次 `/api/sessions` 都重新扫目录

- 位置：`packages/dev-panel/src/server/session-titles.ts:124`（`claudeFile`：`readdir(projects)` 后逐个项目目录 `stat`）、`:149`（`ompFile`：`readdir` 每个会话目录）；`packages/dev-panel/src/server/views.ts:330`、`:331`（每次请求对每格 pane 与每个会话各调一次）。
- 场景：只缓存“找到了”的路径（`located`），找不到的每次重扫。面板以用户级服务运行，若它的环境里没有开发者在 shell 里设的 `CLAUDE_CONFIG_DIR`，或会话来自记录里早已删掉文件的会话，每个找不到的会话每次请求都扫一遍；`/api/sessions` 随 herdr 的状态推送重取，几个会话同时工作时一分钟几十次。
- 依据：实测（tmpfs 上造 300 个 Claude 项目目录、omp 100 个目录各 200 个文件）：5 个找不到的 Claude id 每轮约 26ms，5 个找不到的 omp id 每轮约 50ms，三轮不变（没有负缓存）。单次不大，但随推送反复、随会话数线性增长。
- 建议：记住未命中，给 30 到 60 秒的过期（新会话的文件建在已有的项目子目录里，只看 `projects/` 自身的修改时间判断不出来，所以用过期时间最简单）。

### 9. 建议：omp 的会话值是绝对路径时不限在 omp 的会话目录里，也不查是不是普通文件

- 位置：`packages/dev-panel/src/server/session-titles.ts:150`（`isAbsolute(value)` 时只要求以 `.jsonl` 结尾）、`:77` 起（`cached` 先 `stat`、不看 `isFile()`）、`:198` 起（omp 分支 `readHead` 读前 4KB）。
- 场景：会话值来自 herdr，herdr 的 socket 没有鉴权，本机任何进程都能给一格报会话值，应当按不可信输入处理。Claude 分支用正则挡住了 `..` 与 `/`，并要求 `isFile()`；omp 分支对绝对路径照单全收：会话目录之外、带 `..` 的路径都会被打开并读第一行；值若指向一个以 `.jsonl` 结尾的 FIFO，`open` 会一直等写端，`/api/sessions` 的这次请求就挂住，并占着一个文件线程。能读出的只有第一行里 `type: "title"` 的 `title`，泄露面很小，主要是挂住的风险与两个分支的边界不一致。
- 依据：实测：会话目录之外的 `/dev/shm/.../elsewhere.jsonl` 与 `.../sessions/../../../../elsewhere.jsonl` 都读出了标题；FIFO 挂住从代码推断，没有试。
- 建议：`resolve` 之后要求在 `ompRoot` 下，`stat` 之后要求 `isFile()`（放进 `cached` 让三个分支共用）；`session-titles.test.ts` 补 omp 的越界路径用例（现有的越界用例只测了 Claude）。

### 10. 建议：`cached` 把读取回调里的任何异常都当成“读不出”，编程错误也被吞成 null

- 位置：`packages/dev-panel/src/server/session-titles.ts:88` 到 `:97`（`try { await read(...) } catch { report; return null }`），`:70` 起的 `report` 同一路径只记一次。
- 场景：`parseLine` 特意只吞 `SyntaxError`，但外层 `cached` 的 `catch` 不分类型：`claudeTitleFromTail` 或 Codex 索引的解析里出现 `TypeError` 之类的编程错误，也会变成“这个会话没有标题”，面板日志里每个路径只留一行，之后同一路径再出任何错误都不再记。任务说明要求“读不到或格式不对时为 null，不吞掉真正的编程错误”。
- 依据：从代码推断。
- 建议：`catch` 里只处理带 `systemErrorCode` 的文件系统错误（`stat` 那段同样收窄），其它异常抛出，交给 `/api/sessions` 的统一错误处理；`report` 按“路径加错误码”去重，而不是只按路径。

## 结论

- 阻断 0 条，重要 6 条（第 1 到 6 条），建议 5 条（第 7 到 11 条）。
- 安全与权限边界成立：非 Agent 的 pane 在接管、发文字、按键、WebSocket 输入帧上都被拒，被拒时不调 herdr 的写方法、不写审计；观看与读历史不写审计；白名单只多了只读的 `pane.read`。第 4 条是审计记录的准确性问题，不是越权。
