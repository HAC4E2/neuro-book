## 发现

### 1. 重要：左栏收起或窄屏时，宽 0 的左栏里的条目仍在 Tab 顺序和读屏树里

- 位置：`packages/dev-panel/src/web/App.vue:279-288`（`Splitter` 的导航面板与 `<aside>`），`App.vue:112`（`collapsed: narrow.value || navCollapsed.value`）。
- 场景：窄于 1024px，或桌面上点了“收起左栏”、拖到阈值以内收起之后，导航面板宽 0、`overflow: hidden`，但 `PanelNav` 仍整棵挂在里面。宽 0 与裁切都不会把元素移出 Tab 顺序和无障碍树（只有 `display: none`、`visibility: hidden`、`inert` 会）。于是：
  - 键盘：“跳到主内容”之后的第 2 到第 12 个 Tab 停靠点（品牌、收起左栏、首页、新建、产物、文档、会话、在跑、checkout、GitHub、Work 树、更多）都落在看不见的左栏里，焦点环消失，过完这些才到顶栏的“打开导航”或“展开左栏”；
  - 读屏：窄屏上有两份“面板导航”地标（隐藏的这份与抽屉里那份，抽屉关着时只有隐藏的这份能读到，读到的是一份看不见的导航）；
  - 用键盘按“收起左栏”之后，焦点停在已经看不见的按钮上；按“展开左栏”之后这个按钮被 `v-else-if` 移除，焦点掉到 `body`。
  阶段 2 之前左栏是 `hidden md:flex`，窄屏时不可聚焦，所以这是 2c 引入的回退。验收只测了“第一次 Tab 是跳到主内容”，没有测第二次。
- 证据：从代码推断（nb-ui 与面板的 CSS 里都没有按 `data-state="collapsed"` 隐藏面板内容的规则，已 grep 核对）。
- 建议改法：
  - 给 `<aside>` 加 `:inert="narrow || navCollapsed || undefined"`（保持挂载，只是移出焦点与读屏树；与 `Splitter` 的 id 稳定、正文不重挂不冲突）；
  - 收起后把焦点交给顶栏的“展开左栏”，展开后交给左栏里的“收起左栏”（两个按钮各给一个 ref，`setNavCollapsed` 之后 `nextTick` 再 `focus()`；只在焦点原本就在被移除或被 inert 的那个按钮上时才挪，鼠标拖动收起不挪）；
  - 验收脚本补一条：390 与“收起左栏”之后，连按 Tab 的前三个停靠点依次是“跳到主内容”、顶栏按钮、搜索框。

### 2. 重要：每次推送重取 overview、每次展开别的 Work，Work 树都会被拽回当前行

- 位置：`packages/dev-panel/src/web/parts/PanelNav.vue:109-112`。
- 场景：`watch(() => [props.current.path, allRows.value.length], …)` 的取值函数每次都返回新数组，Vue 按 `Object.is` 比较，所以只要 `allRows` 重算就会回调，与路径、行数变没变无关。`allRows` 依赖 `props.works`，而外壳的 `/api/overview` 订阅了 `records` 与 `activity`：活动的指纹含租约的 `lastActivityAt`、herdr 会话状态与运行列表（`src/server/state.ts:103-110`），Agent 在干活时会频繁变。结果：
  - 在 Task 页上，把 Work 树往上滚去找别的 Work，下一次推送一到，树就跳回当前那一行；
  - 在树上方展开另一个 Work（例如 w00001），插进来的 Task 行把当前行挤出可视区，`revealCurrent()` 立刻往下滚，刚展开的那几行又滚出视野。
  阶段 2 之前左栏不会自己滚，所以这是 2b 引入的。
- 证据：回调触发是实测（`/dev/shm` 下的探针脚本，用集成分支的 Vue：`works` 换成内容相同、长度相同的新数组，回调各触发一次，两次刷新共 2 次）；树被拽回是从代码推断（`revealCurrent()` 只在当前行不在可视区时滚动，正好命中上面两种情形）。
- 建议改法：只在“当前页变了”时把当前行滚进可视区，再加一次性的补偿：当前行第一次出现时（`works` 从 null 到有数据、当前 Work 刚被自动展开）滚一次。例如记一个 `revealedPath`，`watch(() => props.current.path)` 时清空，`flush: "post"` 的回调里只有 `revealedPath !== current.path` 且找到了行时才滚并记下；`measure()` 另挂在 `allRows` 上（它不改滚动，可以保留随数据重量）。

### 3. 建议：当前 Work 被记成“收起”时，进它的 Task 页不会自动展开，当前 Task 不出现、不高亮

- 位置：`packages/dev-panel/src/web/parts/PanelNav.vue:26`（`props.expanded[workId] ?? workId === props.current.workId`）。
- 场景：展开状态记在 `nav-open` 里，键名与阶段 2 之前相同，旧版左栏点过“收起”的 Work 都存着 `false`。对这些 Work，`??` 让记下的 `false` 压过“当前 Work 缺省展开”：从首页、搜索或收件箱点进它的某个 Task，左栏只有 Work 那一行是淡高亮，当前 Task 不在树里，2b 的“Task 页左栏高亮当前 Task”在开发者自己的浏览器里不成立。验收用的是新浏览器配置，没有旧偏好，所以没暴露。
- 证据：从代码推断。
- 建议改法：展开状态归宿主，就在宿主补：`App.vue` 里 `watch(() => navCurrent.value.workId, …)`，进入一个新的 Work（路由的 workId 变了）且它记的是 `false` 时调 `toggleWork(workId, true)`。只在 workId 变化时做，开发者在同一个 Work 里手动收起仍然有效。`PanelNav.md` 的“展开”一条同步改成“进入某个 Work 时展开它”。

### 4. 建议：当前 Work 在“更多”里时，“更多”按钮点了没反应

- 位置：`packages/dev-panel/src/web/parts/PanelNav.vue:23-25`、`:154`。
- 场景：`moreOpen = moreOpenLocal || currentInMore`，按钮做的是 `moreOpenLocal = !moreOpen`。当前 Work 在“更多”里时 `moreOpen` 恒为真，点一下把 `moreOpenLocal` 设成 `false`，`moreOpen` 仍是真：按钮不收起，`aria-expanded` 一直是 `true`，看起来像坏了。
- 证据：从代码推断。
- 建议改法：把“当前 Work 在更多里就展开”做成一次性的打开，而不是常驻的或运算：`watch(currentInMore, (inMore) => { if (inMore) moreOpenLocal.value = true; }, {immediate: true})`，`moreOpen` 只看 `moreOpenLocal`。

### 5. 建议：Work 树对读屏器是一串平铺的链接，层级与方向键模型都没有暴露

- 位置：`packages/dev-panel/src/web/parts/PanelNav.vue:149-168`。
- 场景：树用了 roving tabindex（整棵树一个 Tab 停靠点、方向键走），但容器只是 `section aria-label="工作"`，行是普通 `<a>`，没有 `role="tree"`、`treeitem`、`aria-level`，Task 行与所属 Work 之间只有视觉缩进。后果：
  - NVDA、JAWS 在浏览模式下会吃掉方向键（没有部件角色就不切到焦点模式），`onTreeKey` 收不到；读屏用户按 Tab 只能到一行，其余行只能靠虚拟光标读，听不出哪些 Task 属于哪个 Work；
  - 每个 Work 的展开状态读两遍：展开按钮（`tabindex="-1"` 但仍在无障碍树里，名字是“收起 w00022 的 Task”，带 `aria-expanded`）与 Work 链接上的 `aria-expanded` 各一次。
  键盘本身没有陷阱：Tab 能离开树，方向键在行间走、左右键收放都对。
- 证据：从代码推断（没有用读屏器实测）。
- 建议改法：按 WAI-ARIA APG 的“导航树”做：容器 `role="tree"`（`aria-label="工作"`），Work 与 Task 的链接加 `role="treeitem"` 与 `aria-level`（1、2），`aria-expanded` 只留在 Work 那一项上；展开按钮只服务鼠标，加 `aria-hidden="true"`；“更多”按钮挪到树容器外面（树里只能放 treeitem 与 group）。`PanelNav.md` 的“键盘”一节补一句读屏器的角色。

### 6. 建议：状态点的“数据”一行写死为正常，外壳自己的数据取不到时状态点仍是绿的

- 位置：`packages/dev-panel/src/web/App.vue:236-247`（`lines.push({label: "数据", text: freshness.value, ok: true})`），`App.vue:253-264`（横幅只从 `meta.data` 来）。
- 场景：外壳有三份自己的资源（`/api/overview`、`/api/meta`、`/api/notify`），`useResource` 已经给出 `error`、`stale`、`receivedAt`，外壳一样都没用：
  - 推送连着、但 `/api/overview` 或 `/api/meta` 重取失败（500、服务端读记录出错）时，左栏的 Work 树、计数、收件箱数与横幅都停在上一份，状态点是绿的，“数据”一行仍写“X 分钟前读到”；
  - `/api/meta` 第一次就失败时 `meta.data` 一直是 null：herdr 那一行不出现，所有横幅（含“前端构建失败”“审计未开启”）都不会出现，状态点是绿的“状态：正常”。
  阶段 2 之前数据新旧一直写在顶栏上，开发者能自己看出“很久没更新”；现在收进状态点的详情里，又永远不会把点变黄，这一类异常就被藏起来了。阶段 1 给页面加了 `StaleNotice`，外壳这三份资源没有对应的提示。
- 证据：从代码推断。
- 建议改法：“数据”一行的 `ok` 取 `!overview.error.value && !meta.error.value && !notify.error.value`（或 `stale` 加首次失败），失败时文字写“重取失败：<原因>，显示的是 <receivedAt> 读到的”，点变黄；`meta.data` 为 null 且 `meta.error` 有值时，状态点写“状态：读不到面板状态”。不要按 `parts.records.at` 的年龄判断：没有变化时它本来就会很旧。

### 7. 建议：抽屉没有登记触发器，Esc 或关闭按钮关掉抽屉后焦点掉到 body（顺带回答“还焦点与外壳挪焦点会不会打架”）

- 位置：`packages/dev-panel/src/web/App.vue:292`（“打开导航”在顶栏里，只改 `drawerOpen`），`App.vue:332-334`（`Drawer` 没用 `#trigger` 插槽）。
- 场景：读了 reka-ui 2.10.3 的 `DrawerContent`：模态抽屉关闭时的 `closeAutoFocus` 先 `preventDefault()`，再 `rootContext.triggerElement?.focus()`；触发器只由 `DrawerTrigger` 登记，这里的 `#trigger` 插槽是空的，`triggerElement` 解析成空（空插槽的注释节点后面没有元素）。所以：
  - 计划“没有验证到的地方”担心的打架不会发生：抽屉不会把焦点还给“打开导航”，从抽屉里点导航之后，外壳的 `focusPageHeading` 照常生效（焦点原在被移除的链接上，落到 body 之后仍算“没挪过”，标题出现就过去）。这一条是从代码推断，仍建议在 390 上实测一次；
  - 反过来，用 Esc、遮罩或右上角的关闭按钮关抽屉时，焦点也没有人接，掉到 body，键盘用户要从文档开头重新 Tab。WAI-ARIA APG 的模态对话框模式要求关闭后焦点回到打开它的控件。这一点阶段 2 之前就是这样，2c 改的正是这块，顺手修最便宜。
- 证据：从代码推断（reka-ui 源码 `dist/Drawer/DrawerContent.js:90-94`、`dist/Drawer/DrawerTrigger.js:24-29`、`dist/shared/useForwardExpose.js:12-14`）。
- 建议改法：本 Task 不改 nb-ui（D3），所以在外壳补：`Drawer` 的 `update:open` 变成 `false` 且路由没变时，等抽屉卸载后（下一帧之后）焦点仍在 body 就聚焦“打开导航”；路由变了就交给 `focusPageHeading`。长期做法记进后续清单：nb-ui `Drawer` 透出 `closeAutoFocus`，或允许宿主指定外部触发器。

### 8. 建议：加一个新页面要动的几处散在三个文件里，没有写成一处清单；外壳顶部注释已过时

- 位置：`packages/dev-panel/src/web/host/nav.ts:62-80`（`PAGE_NAMES` 按路由名字符串取页面名）、`packages/dev-panel/src/web/router.ts:3-11`（`RouteMeta.layout`）、`packages/dev-panel/docs/panel.md:391-393`、`packages/dev-panel/src/web/App.vue:16-21`。
- 场景：现在加一页要做四件事：`router.ts` 写路由名（铺满型再写 `meta.layout`）；`nav.ts` 的 `PAGE_NAMES` 加页面名，否则标签页标题静默退回“nbdev”；顶层入口还要进 `NAV_GROUPS`；页面要有且只有一个 `h1` 当页标题，否则换页时焦点等 5 秒落空、“跳到主内容”只能落到 `main`（现在文档页靠 Markdown 正文里的 `h1`，没选文档时没有；找不到页面也没有）。这些分别写在 `panel.md` 的“外壳”“可访问性”“滚动”三条里，没有一处告诉后来者“加页面照这几步做”。`PAGE_NAMES` 的键与 `router.ts` 的路由名之间没有类型联系，改名或漏写都不报错。另外 `App.vue` 第 17 行的注释仍写“顶栏（搜索、数据新旧、代码已更新、通知要处理的计数、审计、herdr、明暗）”，2d 之后顶栏只剩搜索、状态点、通知与明暗，代码已更新与审计在横幅里。
- 证据：从代码与文档推断。
- 建议改法：
  - 页面名挪进路由元信息，和 `layout` 放在一起（`RouteMeta` 加 `title?: string`），`pageTitle` 只处理要拼参数的几种，其余读 `route.meta.title`，路由与名字在一处声明；
  - `panel.md`“前端”加一条“加一个页面”：路由名与 `meta`、是否进 `NAV_GROUPS`、页面有一个 `h1`、流式页面不要自己再包一层竖向滚动；
  - 更新 `App.vue` 顶部注释。阶段 3 的 `PageShell` 会统一给页标题，可以在那时把“页面要有 `h1`”收进 `PageShell`。

### 9. 建议：“一页一个竖向滚动者”写成了绝对规则，会话页里仍有几块自己竖向滚的预览，文档没有交代这个例外

- 位置：`packages/dev-panel/docs/panel.md:393`（“滚动”一条），`packages/dev-panel/src/web/parts/SessionConsole.vue:62`（`max-h-96 overflow-auto`）、`packages/dev-panel/src/web/pages/SessionsPage.vue:142`（`max-h-[40vh]`）、`packages/dev-panel/src/web/parts/TerminalTextView.vue:46`（`max-h-[60vh]`）、`packages/dev-panel/src/web/parts/NotifyStatus.vue:113`、`DiffView.vue:14`、`CreatePreview.vue:34`。
- 场景：会话页选中一格、屏幕文字或更早的输出较长时，`main` 在滚，里面的 `pre` 也在滚，同屏两条竖向滚动条；滚轮停在 `pre` 上时先滚它、到头再带着 `main` 滚。2a 的验收只量了“内容区最多一条”，量的那一刻这些块没有溢出。会话页改成铺满放在阶段 4（审查建议 6），这本身没问题；问题是 `panel.md` 现在写“一页只有一个竖向滚动者”，后来者读到的规则与代码不一致，也不知道有上限高度的预览块算不算违规。
- 证据：从代码推断。
- 建议改法：`panel.md`“滚动”一条补一句例外：有上限高度的预览块（屏幕末尾、差异、文件预览）可以自己滚，不算页面的滚动者；页面的主体不再套第二层竖向滚动。顺带：`.nbdev-scroll-y` 与 nb-ui 已有的 `.nb-ui-scrollbar-stable` 是同一件事的两种写法，文档页又用了第三种（`[scrollbar-gutter:stable]`，因为要带 `md:` 前缀），可以在 `app.css` 的注释里说明为什么不用 nb-ui 的类，免得阶段 3 收语义类时再分叉。

### 10. 意见（委托第 8 点）：“审计未开启”的常驻横幅应当分情形处理，`not_initialized` 改成可关

- 位置：`packages/dev-panel/src/web/App.vue:258`。
- 判断：审计有两类“没开”，性质不同，现在用同一条不可关的横幅：
  - `not_initialized`：开发者还没跑 `audit-init`，多半是有意不用发通知与代打字。这是一台机器的配置状态，不是故障，也不会自己变；它影响的两件事在用到的地方已经各有说明：会话页“通知”一节写了原因与命令（`SessionsPage.vue:125`），会话控制台的不可用原因也写了（`SessionsPage.vue:93`）。常驻在每一页顶上，只会让人习惯性忽略横幅区，真正要处理的“代码已更新”“前端构建失败”“后台重算失败”就跟着被忽略。
  - `bad_owner`、`bad_mode`、`not_regular`、`unreadable`：初始化过、后来坏了（权限或文件被动过）。这是故障，审计日志的可信度出了问题，应当常驻、不可关。
- 建议改法：
  - `not_initialized` 的横幅给一个“知道了”，记在 `host/prefs.ts`（键按“原因 + 审计文件路径”记，换了机器、路径或原因会重新出现），关掉之后在状态点的详情里留一行“审计：未开启”（不把点变黄）；
  - 其余原因保持现在的常驻横幅，不给关闭；
  - `docs/panel.md`“外壳”一条同步写明这两种的区别。
  不建议整条改成可关：坏掉的审计被一次“知道了”永久藏起来，比吵更糟。

## 核对过、没有发现问题的地方

- `Splitter` 接线（`App.vue:96-129`）：`panels` 是 `computed`，只随用户宽度、收起、视口宽度变，外壳每 15 秒的时钟重渲染拿到的是同一个对象，不触发重新分配；`sashSizes` 每次渲染是新数组，但组件按 `join(",")` 的键比较，也不触发。`defaultSizePx` 绑用户要的宽度、`maxSizePx` 取 `min(480, 视口 40%)`，重新分配幂等，窗口变窄夹住、变宽恢复；`gesture-end` 先回写 `collapsed[导航]` 再记宽度，宽度只在拖完或键盘按键抬起时写一次 prefs，夹住时不写；收起类型用 `NonNullable<SplitterPanelConfig["collapse"]>`，没有深导入 `grid-types`。窄屏沿用同一个 `Splitter`，面板 id 不变、`v-for` 按 id 取键，正文不重挂（验收里 textarea 同一元素、`/ws/terminal` 只握手一次）。
- 快捷键（`host/shortcuts.ts`、`App.vue:146-158`）：在 `document` 冒泡阶段监听，没有捕获阶段的 `preventDefault`；输入框（非文字类 input 除外）、`textarea`、`select`、`contenteditable`、`.xterm` 内、`role=dialog/alertdialog` 内、组字中、已被拦下的按键都不处理；登录失效时不处理。nb-ui `Popover` 与 `Drawer` 的内容是 `role="dialog"`，也在排除之列。新增的三份单测在集成分支上跑过：`bun test --isolate tests/nav.test.ts tests/shortcuts.test.ts tests/terminal-colors.test.ts`，6 过 0 败。
- 焦点（`App.vue:160-213`）：只在 `pageKey`（路由名加路径参数）变化时挪，查询参数变化不挪；起始位置第一次解析不算换页；等标题时开发者挪过焦点、或焦点在可编辑元素上（例如顶栏搜索提交后）就不抢；`preventScroll` 避免数据晚到时页面跳动；换页时 `stopHeadingWait()` 清掉上一轮的观察者与定时器，卸载时也清。
- 横幅来源：服务端 `meta.parts` 只有 `records` 与 `activity` 两块（`src/server/serve.ts:165`），横幅覆盖了代码已更新、构建失败、审计、后台重算失败四类，与计划一致；推送与 herdr 在状态点里。

## 结论

- 阻断 0 条，重要 2 条，建议 7 条，另有 1 条委托的意见（审计横幅）。
- 两条重要都是阶段 2 引入的回退，改动都很小：第 1 条（宽 0 的左栏仍可聚焦，窄屏与收起时键盘要穿过约 11 个看不见的停靠点）给 `<aside>` 加 `inert` 并交接焦点；第 2 条（推送一到、展开别的 Work，树就被拽回当前行）把“滚进可视区”限定在当前页变化时。
- 能不能合入：修掉这两条、补一条 390 与收起状态下的 Tab 顺序验收之后可以合入。建议项里第 3、4 条（当前 Work 记成收起时不自动展开、“更多”按钮失灵）也很便宜，建议一起改；其余（树的读屏角色、状态点的数据一行、抽屉还焦点、加页面清单、滚动例外的文档）可以并入阶段 3 或记进后续清单。
