# t15 改动方案

依据：四份审查报告（本地 `.local/agent/works/w00022-dev-panel/tasks/t15-ui-polish/reports/` 下的 `ux-a.md`、`ux-b.md`、`ux-c.md`、`omp-frontend-review.md`，截图在同目录的 `shots/`），以及开发者试用时的四条建议（[后续清单](../../followups.md)）。

## 审查结论概要

| 审查 | 范围 | 严重或阻断 | 重要 | 建议 |
|---|---|---|---|---|
| ux-a（sonnet） | 信息架构、视觉层次 | 0 | 6 | 7 |
| ux-b（sonnet） | 任务流程、交互反馈 | 2 | 9 | 6 |
| ux-c（sonnet） | 滚动条、响应式、可访问性 | 0 | 11 | 10 |
| omp | 前端代码设计 | 1 | 9 | 6 |

四份报告指向同几个根：

1. **外壳没有约定**：左栏随 Work 数量变长，把“资料”“现场”挤出首屏，Task 页不显示当前位置；桌面左栏与手机抽屉是两份导航，已经分叉；没有滚动条样式，也没有“谁来滚”的约定。nb-ui 给 `html` 预留滚动条槽位，面板整页不滚，窗口右边永远空 15px。
2. **页面没有骨架**：标题位置、面包屑、操作区各页不同，主要操作是 11px 的灰字；字号、间距、底色靠内联样式各写各的。
3. **反馈与状态零件不统一**：成功被染成警告色，错误重复三遍并把编辑器往下推；后台重取失败时界面照常显示旧数据，不提示。
4. **现场类页面只给计数、不给下钻**：checkout 的“未提交”不算新文件，会显示成“干净”；没有 Agent 会话的 pane 在面板里看不了；文档页只标“改动”，看不到改了什么。
5. **宿主里的异步状态有几处身份错位**，omp 用隔离实验复现：
   - 阻断：会话确认没有绑定目标。确认框打开期间，这格 pane 的会话换了（或者选中换了），按下确认后，按键会发给新的会话。
   - 换终端源后，零件不重新订阅：画面还是旧终端，输入却发给新终端。
   - 编辑页换文件后草稿不换；保存期间继续输入的字，会被保存成功的回应盖掉。
   - 写请求遇到 401，不进入全局的“要重新登录”。
   - 推送连续到来时，慢资源一直被中止、取不到。
   - 标签页在后台时第一次建终端，切回前台后不会连上。

做得好、应保留的：写入链路（预览、字段报错、哈希冲突保护、提交号反馈、离开拦截、后退与深链接）、接管键盘的确认、产物页实时合并新题、零件只经 props 与 emits 的分工。不推倒重写。

## 分阶段

每一阶段可单独合入、单独验收；在集成分支 `feat/w00022-dev-panel` 上做，先从 `master` 同步。

### 阶段 1：行为缺陷（不改外观）

omp 的阻断 1 与重要 3 到 9。会话确认改为在打开时捕获 `{paneId, terminalId, sessionKey}`，目标变了就取消；终端零件按终端身份重建；编辑页的编辑会话带上路径身份，保存期间只读；401 统一进全局登录失效状态；同一资源的重取改为单飞，期间再有失效只补取一次；已有数据时重取失败要显示“这是上次读到的内容”，并给重试；后台首次建连记为暂停，回到前台时恢复。

先做这一阶段：阻断那条涉及向错误的会话发按键，开发者正在用面板。

### 阶段 2：外壳（开发者第 1、2 条）

- **导航零件**：抽出 `PanelNav`，桌面左栏与手机抽屉共用一份。左栏分两段：
  - 上段固定：首页与收件箱、新建、资料、现场，带计数；
  - 下段：可滚动的 Work 树。
  - 进入 Work 或 Task 时，按路由自动展开所属 Work、高亮当前项，并滚进可视区。
  - 被截断的标题悬停时显示全文。
- **可调宽度**：用 nb-ui 的 `Splitter`。它自带像素尺寸、上下限、键盘调整、Esc 取消与分隔线语义；面板不另写拖动逻辑，也不深导入 nb-ui 内部的 `useSashGesture`。
  - 宽度经 `host/prefs.ts` 记住，只在拖完时写一次。
  - 窄于 `md` 时仍用抽屉；断点切换时 `RouterView` 不重挂，编辑草稿和终端不丢。
  - 拖动期间屏蔽产物页 iframe 的指针事件。
  - 尺寸见决定点 D4。
- **滚动条**：
  - 面板 `app.css` 一处声明细滚动条（标准属性 `scrollbar-width: thin` 加由 `--text-muted` 派生的半透明配色，悬停加深），明暗都跟主题；
  - `html` 改回不预留槽位，去掉右边 15px 的空白；
  - 左栏的 Work 区、`main`、文档页两栏用 `scrollbar-gutter: stable`，内容溢出与不溢出切换时宽度不跳；
  - 约定“一页一个竖向滚动者”，铺满型页面（文档、会话）在路由元信息里声明，由外壳决定 `main` 滚不滚；
  - xterm 的滚动条：ux-c 实测 `.xterm-viewport` 恒占 15px，omp 读 xterm 6.0.0 的源码认为它是自绘条，两边说法不一，实施时先实测，再定是隐藏还是用 xterm 主题配色。
- **顶栏**：
  - 搜索框限宽，加 `/` 与 Ctrl+K 聚焦；
  - 正常状态（herdr 已订阅、推送已连、数据新旧）合成一个状态点，点开看详情；
  - “代码已更新”“前端构建失败”“审计未开启”改成顶栏下的一条提示横幅；
  - “通知要处理”保留醒目。
- **可访问性小项**：
  - 加“跳到主内容”，路由切换后把焦点放到页标题；
  - 每页的 `document.title` 写成“页面名 · nbdev”；
  - 焦点环用 nb-ui 的焦点令牌；
  - 承载信息的灰字（表头、编号、元信息）改用 `--text-secondary`：亮色下 `--text-muted` 的对比度只有 2.88:1。

### 阶段 3：页面骨架与共用零件

- `PageShell`：面包屑、标题、状态、右上操作槽，内容宽度分三档（阅读、列表、满铺），14 个页面都套它；文档页、编辑页补上页头。
- 少量 `nbdev-` 前缀的语义类，统一字号五档（页标题、区标题、正文、说明、标注）和区块间距，代替散落的内联 `style`。
- 操作分两级：主要操作用 `Button`，次要操作用带文字的 ghost 按钮；不再用 11px 的灰字当按钮。
- 反馈零件分两层：
  - 结果（成功、失败、冲突、结果未知）：颜色只由结果决定，位置固定，不推动内容；
  - 附注（警告）：缩进、可折叠。
  - 字段错误只报一次，并锚到字段上。
- `LoadState` 加骨架屏变体，并加“显示的是旧数据”的提示变体；404 与网络错误分开，404 给“回到上一级”的链接，不给“重试”。
- 截断零件：截断，悬停看全文，点击复制。长 id、路径、分支名都用它；数字用等宽数字。
- “临时”虚线框收敛：现场页整页都是临时内容，改为分区标题旁一个“临时”小徽标；虚线框只留给混在持久页面里的临时片段，例如 Task 页的“谁在动”。

### 阶段 4：逐页改进

- **首页**：
  - 第一屏放“等我”：待答的提问按产物合并（开发者第 4 条，例如“uxq：3 道待答”），要处理的通知，异常；
  - 撞号写明原因，并给出去哪里处理；
  - Work 排序：有事等我的在前，其次进行中，再按最近更新；卡片改紧凑。
- **Work 页**（开发者第 1 条）：
  - Task 行可以就地展开，展开后显示当前情况、下一步、产物、证据、谁在动；
  - 标题列加宽，单行截断；
  - “当前情况”按行内 Markdown 渲染，不再露出 `[链接](…)` 源码；
  - 为 0 的计数淡化显示。
- **Task 页**：
  - 开发者第 2 条：Markdown 右边那片空白。ux-a 在文档页、Task 页都看到正文只占左边一部分，可能和正文 72ch 的阅读宽度有关，实施时核实；
  - 状态只显示一处；
  - 产物、证据、文档改在侧边速览面板里打开（开发者第 3 条，见 D1）。
- **产物页**：
  - 分“待答、已答（只读回看答案、时间、版本）、已取代”三段；
  - 新加的题标“新”；
  - 提交栏固定在底部，写明“已改几题、还有几道必答”；
  - 成功提示写答了什么，不只给提交号。
- **会话页**：
  - 改成左列表、右详情两栏，选中项高亮；
  - 终端定高，输入框、按键行、投递结果紧贴终端；
  - 写明发送快捷键；接管时给一个固定的退出组合键，并写在提示条上；
  - 观看对象是否扩到任意 pane，见 D2。
- **现场三页**：
  - 会话页里的“无主的运行”只留一个去“在跑”的入口；
  - checkout 的“未提交”分已跟踪与未跟踪两个数，点开看文件清单；这一项要改服务端，现在是 `git status -uno`；
  - 整行可点，去对应的 Task 或文档；
  - 落后、有改动、有服务在跑这几种需要注意的状态，用同一种颜色突出。
- **文档页**：
  - 加“渲染 / 与 master 的差异”切换；
  - “只看有差异的”和所选 checkout 都写进网址；
  - 手机上把文档树收进抽屉。
- **编辑页**：
  - 加面包屑，能回到 Task；
  - 底部固定操作栏：保存并提交、放弃，支持 Ctrl+S；
  - 站内离开时用面板自己的确认框，不用浏览器原生的。
- **搜索**：
  - 记录类的命中放第一屏，按相关度排序；
  - 文件命中高亮关键词；
  - `.agents/tasks` 的历史默认折叠。

## 要开发者定的

- **D1 在 Task 页看产物、证据、文档，怎么才不整页跳走**（开发者第 3 条）。推荐**侧边速览面板**：
  - 从 Task 页点产物、证据、文档时，右侧滑出一个面板显示内容；
  - 面板状态写进网址，例如 `?peek=…`，能后退、能分享；
  - 中键点击仍在新的浏览器标签页打开。

  备选：
  - 面板内自建标签页：和浏览器标签页重复，状态管理重；
  - 浮动窗口：桌面上灵活，但窄屏和键盘都难做好。
- **D2 会话页能不能只读观看没有 Agent 会话的 pane**，例如在跑的服务、构建日志（ux-b 严重 2）。推荐**能看**：
  - 只读观看，不给发消息；
  - 接管仍然只开放给 Agent 会话。普通 shell 的接管在后续清单里，继续推迟。
- **D3 滚动条样式放哪**。推荐**先放面板自己的 `app.css`**：
  - 放进 nb-ui 让两边共用会改到主应用的外观，主应用正被 w00017、w00019 两个会话在改；
  - 收进 nb-ui，并补规范第 15 条的缺口（`html` 槽位、ScrollArea 与原生 CSS 的分工），记进后续清单，交给 nb-ui 那边。
- **D4 左栏尺寸**。三份审查给的数不同：
  - ux-a：默认 272，最小 208，最大 400；
  - ux-c：默认 320 到 340，最小 200，最大 480；
  - omp：默认 248，最小 200，最大 360。

  推荐默认 300、最小 200、最大取 480 与视口 40% 中较小的，拖到最小以下就收起，再给一个显式的收起按钮。

  Work 树默认只列“进行中”和“30 天内更新过的未标” Work，其余收进“更多”。现在会列出全部进行中与未标的，共 22 个。
- **D5 次序**。推荐 1 → 2 → 3 → 4，每阶段完成后单独合入 `master`：
  - 阶段 1 先做、先合入；
  - 每次合入都要重启常驻服务，重启后浏览器要重新登录，所以重启前先问开发者。
