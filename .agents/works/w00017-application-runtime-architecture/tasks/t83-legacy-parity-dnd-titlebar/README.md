# 拖放与标题栏对照旧应用

## 目标与范围

开发者 2026-10-12 手动审查 t79 时提出，选择另开 Task，先调研出差距清单再定设计。

- **移动视图与容器**（开发者认为最严重）：旧应用有落点区域指示和动画，新应用不如它完善。
- **标题栏宽度自适应**：开发者认为旧应用的更完善。
- **多级菜单**：旧应用用了多级菜单。

不含：菜单浮层的圆角与阴影（归 t79）。行为合同在定下范围后改 [`ui/workbench-shell.md`](../../../../../docs/specs/ui/workbench-shell.md)（外壳三的拖放、输出 28 与 39）。

## 当前状态

- 2026-10-13 调研完成，差距清单见 [artifacts/gap-review/index.html](artifacts/gap-review/index.html)（左旧右新的对照图与帧条）。
- 做法：旧应用取 master `c3c47d5d`，在只读参照 worktree `.worktree/w00017-t83-legacy-ref`（分离在 master，自己 `bun install`）里用临时状态目录跑在 4321 端口；本分支上的旧包缺仓库根的构建脚本，起不来。新应用用 t79 的临时开发会话（4317）。两边新建同名作品，用同一个 Playwright 脚本做同样的拖动，经 Chrome 屏幕流录下带时间戳的帧；标题栏在 14 个宽度下各拍一张，菜单逐个打开列出条目。
- 2026-10-13 开发者补充：旧应用拖视图时有分栏（面板标签带是 Switcher，每个 ViewContainer 可分栏）。补测：旧应用用 Lab 的多容器场景，新应用用 e2e 测试插件 `test.sample-views` 起了带六个样例视图的服务；面板多容器、容器内横排分栏、拖到半区并入两边一致，新产品只有一个视图所以体验不到（清单 D6）。
- 主要结论：拖放判定与落点覆盖层两边几乎是同一套，淡入与换目标的过渡两边都有，松手后两边都没有动画；新应用默认布局里空右栏与面板不显示（输出 39），拖动时没有任何落点，这是“没有落点指示”的主因。标题栏旧应用逐级让位、搜索占满中间、有回差，新应用三档一刀切。多级菜单旧应用只用在窄宽度的收拢菜单。

## 开发者的决定（2026-10-13）

按清单末尾的六项：

1. D1 选 a：拖动开始时把隐藏的空右栏与面板临时显示成落点，放进去就留下，取消或放到别处就收回。
2. D2 做：空 Part 的占位改为整块虚线框、文字居中。
3. D3 做：nbook 下加深落点高亮。
4. D4 做一个放下后的布局过渡（旧应用没有，属于新增）。
5. 标题栏按推荐的顺序逐级让位：横排标志换成图形 → 菜单收成 ≡ → 收快捷键提示 → 收布局按钮 → 项目名只留图标；搜索取中间剩余宽度，上限 560px；每档加回差。
6. M1 做：收拢菜单改成按组的子菜单。M2 没有给推荐，先不做。

另加三项：

7. 分栏：分栏视图的标题整行可以点击收起；栏与栏之间的边界太明显，改用开放式分割线（两端不碰到头的短线，同活动栏与侧栏之间那条）。
8. 核对并优化各种状态下的拖放行为，例如分栏收起时的拖与放。
9. Switcher 的标签太多时怎么显示，优化一下。
