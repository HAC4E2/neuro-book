已定每项用混合排法

要你定：窗口固定 960 后，通用列表每一项用哪种排法。

  • 标签列加控件列：标签列约 200px，控件紧跟其后、左对齐。项少的分区右边会空出一块。
  • 竖排（VS Code 式）：标题、说明、控件从上往下，控件左对齐、不拉满。说明可以写长，适合说明多的项；每项更占高度。
  • 混合：开关、分段、下拉、数字、单行输入用标签列加控件列；多行文本、JSON、列表这类宽控件另起一行、占满内容列。旧设置里这类宽控件不少：压缩提示词、摘要前缀、嵌入的请求扩展参数、模型的请求头。
开发者定：混合。简单项保持紧凑，多行文本和 JSON 铺满内容列，宽控件把右边的空白吃掉，读起来最均衡。竖排的代价在编辑器上最明显：13 项要滚两屏多，开关单独占一行很空。现在的外观、作品两个分区全是简单控件，混合和“标签列加控件列”画出来一样；“这一项是长文本”要在声明里加一个提示，等 Agent 或向量嵌入迁回、有第一个使用者时再加。

Agent 运行策略与向量嵌入是按旧应用的内容模拟的，现在还没有这些插件，只用来看宽控件。窗口 640 高，长分区另附“滚到底”的图。

已定窗口宽度：固定 960

开发者选固定宽 960×640，切换分区时不变大小，可拖动调整、尺寸按客户端记住。780 宽放不下自带二级列表的页面（例如模型配置），按页面自动变宽又会让窗口在切换时跳动。

已定入口：和头像放在一起（P1）

P1：工作台活动栏最下面头像在上、齿轮在下；书架右上角齿轮在头像左边。不做头像菜单（P2）：头像菜单若归账户插件，不装账户插件就没有设置入口。

已定插件自己画的整页

整页分 column 与 fill 两种版式；分区标题与说明一律由设置窗口画；fill 页面里的二级列表用设置插件导出的页内列表组件，选中样式与左栏不同。

已定每项标题在左、控件在右

第一轮选 R1；第二轮比较了窄内容列（R1a）与标签列加控件列（R1b）；960 宽下的最终排法见最上面的待定问题。

已定用户与本作品两层（L1）

顶部切换“用户 | 本作品”，每个分区有明确的目标层，整页按 context.layer 读写。旧设置的“启动”档不进设置界面；“本机”层只在合同里留位置。

已定浮动窗口加左侧分区（A）

书架页没有编辑区，所以不做编辑区标签（C）；改主题时窗口不挡住后面，能直接看到效果。
