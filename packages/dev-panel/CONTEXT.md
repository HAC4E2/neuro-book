# dev-panel 术语与不变量

由 w00022 的[领域模型](../../.agents/works/w00022-dev-panel/tasks/t03-design/domain-model.md)第三节搬入，补上 [Proposal](../../docs/proposals/dev-panel.md) 与 t06 的新词。

## 两层

- **项目数据**（持久，入库）：Work、Task、产物、提问、答复、证据，只放主工作区 `master` 的 `.agents/works/`，只有一份。
- **运行时**（临时，不入库）：会话、租约、通知、运行，记在主工作区的 `.local/agent/` 或内存里。

不变量：

1. 项目数据里没有任何字段指向会话（发布记录、答复、确认都没有）；运行时只按 id 引用项目数据，“谁问的、谁代录的”记在运行时的 provenance 里。
2. 记录只有一份：Work 与 Task 的记录只在 `master` 上维护；实现分支只带代码、Spec 与文档的改动。
3. 答复只追加，不改已有的答复。
4. 决定只认 Task 记录；答复是它的来源。
5. 项目数据与登记表的写入经同一个写事务（锁、落位、路径限定提交），命令行与面板共用一套实现。租约是运行时数据，不进写事务：每份按 leaseId 原子替换，有效性在读取时现算（Task 已 done 或 shelved、会话进程不在都直接判无效），所以写入的竞争不会让已关闭的 Task 重新有人“在动”。竞争只会让“谁在动”短暂少算一个会话，到它下一次 Task 相关操作就恢复（细节见 docs/file-formats.md 的租约一节）。

## 项目数据

**Work**：一个有目标、有范围与授权的事情；记录在 `master` 的 `.agents/works/<workId>/README.md`，有状态（`active`、`done`、`shelved`）与“目标”一节。
_Avoid_：项目、工单、本地 Work（已取消）

**Task**：Work 里一个可单独执行与验收的切片；状态取 `planned`、`active`、`done`、`shelved`，写在 frontmatter 的 `status`。“有几个待答提问”这类是现算的，不存进状态。
_Avoid_：任务卡、子任务

**记录**：Work 与 Task 的 README，是目标、范围、授权、决定与当前情况的真相源。
_Avoid_：文档、快照副本

**master 来源**：已提交到 `master` 的记录。只在主工作区工作树里、还没提交的记录照样列出，标“未提交”，但不能经 nbdev 写。

**来自分支**：过渡期内，记录还在某个实现分支上维护的 Work（分支上有自分出以来新增或改过、且与当前 `master` 仍不同的记录文件）。nbdev 从它的**执行 worktree** 读，不写它；经 nbdev 新建的 Task 一律写进 `master`。

**执行 worktree**：来自分支的 Work 从哪一份 checkout 读；依次按登记表的 `home` 提示、目录名、最近改动来认，其余列为副本。

**决定**：开发者拍板后由会话写进 Task 记录的一条文字。

**产物**：会话交给开发者看的页面，属于某个 Task（少数属于 Work），分设计稿、讲解与报告、审查报告；有版本。Task 目录里的 Markdown 算**文档类产物**，按文件索引，没有发布记录。
_Avoid_：讲解页、附件

**提问**：要开发者拍板的一件事；有四种结局：`open`、`answered`、`withdrawn`、`superseded`。
_Avoid_：问题单、待办

**答复**：开发者对一个提问的回答，持久、只追加。
_Avoid_：回复、反馈

**发布记录**：产物的一个版本（`versions/v<N>.json`），带这一版的全部题与各自的结局；之后不改。题的结局写在最新一版里，是否已答由答复现算。

**提问集**：挂在 Task 上、没有页面的产物（`artifacts/questions/`），`nbdev ask` 登记的题默认记在这里。

**代录**：会话把开发者在会话里口头给的答复记成一份答复（`submittedBy.kind: "agent-transcribed"`）。

**确认**：会话读到答复、把决定写进 Task 记录之后写的一份文件，与写了决定的记录同一个提交；它覆盖哪些答复写在里面。还没被任何确认覆盖的答复是**未确认**的：有未确认答复的产物是“等会话采纳”，都已确认的是“已采纳”。

**收件箱**：只放要开发者动手的事：还没答的必答题与撞号。会话在等的事只认登记成提问的，不从终端推断。

## 编号

**领号**：经 nbdev 在锁里扫描所有来源、取最大值加一、建最小 README 并提交。

**登记表**：`.local/agent/registry.json`，只记领号的事实（编号、领号时间、状态 `claimed`、`imported`、`abandoned`、执行位置提示 `home`）；三种号都不再发。标题、进度、状态一律读 README。登记表不是可重新生成的原始输出：重建只能恢复 `imported`。

**撞号**：同一序号出现两个以上不同的 id。`live` 表示至少两个 id 不是 `master` 改名或删除后留下的旧副本。

**写事务**：取锁、计算、登记、落位（新目录整体改名、新文件独占创建、改文件先比哈希）、路径限定提交、放锁。

## 运行时

**会话**：一次 Agent 对话（Claude Code 或 omp），以会话 id 认人；pane 只是线索（会话会换 pane，pane 上也会换会话）。会话是否还在看它的进程（pid 加启动时刻），不看 herdr 的列表。

**外部会话**：不在 herdr 里、用 `--as <标签>` 标明自己的调用者，例如开发者手动起的 `omp -p`。标签要唯一。

**未知调用者**：既没有 `--as`、也没有可信的会话环境变量的调用者；写命令照常完成，但不取得租约。

**租约**：某个会话正在某个 Task 上做事的临时事实；会话进程不在、Task 已关闭、或 24 小时没有 Task 相关操作即失效，不入库。
_Avoid_：参与、绑定、分配、所有者

**运行**：会话派出、在后台完成的一件事（omp 编码与审查、测试、开发服务）；运行不持有租约。只认 Agent 工具派出的进程（带 `CLAUDE_PID` 或 `OMPCODE=1`）。

**无主的运行**：普通 shell pane 里起的进程，或 systemd 服务单元里的进程；nbdev 认得出它在跑，认不出是哪个会话派的。

**通知**：答复后经 herdr 投给提问者会话的一行指针消息，投递方式 followup 或 steer。
